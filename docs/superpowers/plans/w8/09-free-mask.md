# F9. 자유 마스크 (펜 툴)

## 무엇을 하나

**화면의 아무 모양이나 오려낸다.** 지금 마스크는 사각형·원·가로띠 **3종**뿐이라
「사람만 남기고 배경을 지우기」·「간판만 흐리게」·「하늘만 색을 바꾸기」가 안 된다.
점을 찍어 만든 자유 곡선(펜 툴)으로 마스크를 그릴 수 있게 하고, 그 경계를 부드럽게(페더)
만들 수 있게 한다.

**렌더 쪽은 쉽다 — 순수 CSS·SVG 로 되고 새 npm 패키지도 필요 없다.**
**어려운 것은 UI 다.** 펜 툴 편집기(정점 추가·삭제, 베지어 핸들, 닫기, 되돌리기)가
이 작업의 8할이다. 그 사실을 이유로 「사각형 여러 개로 대신」 같은 축소를 하지 않는다.

## 렌더 — 두 갈래

### 하드 엣지: `clip-path: path()`

```css
clip-path: path("M 120,80 C 200,40 320,60 400,140 L 380,300 Z");
```

**단위가 px 뿐이다** — 퍼센트도, `var()` 도, `calc()` 도 안 된다(CSS Shapes 규격).
보통은 이게 골칫거리지만 **kitkat 에서는 오히려 맞는다:**

`computeVisualLayout` 이 돌려주는 `layout.box` 가 이미 px 이고
(`clips.tsx:130-134` 에서 `left/top/width/height` 에 숫자를 그대로 넣는다),
마스크가 걸리는 요소가 정확히 그 상자다(`clips.tsx:149`). **`d` 를 px 로 바꿀 자리가 이미 있다.**

`path(evenodd, "…")` 로 구멍(도넛)도 뚫린다.

### 페더: `clip-path` 로는 **안 된다**

`clip-path` 는 안티에일리어싱(계단 없애기)만 있고 **페더(경계를 몇 px 에 걸쳐 서서히 투명하게)가
없다.** 이건 규격상 없는 것이지 브라우저 문제가 아니다.

**표준 해법은 SVG `<mask>` + `feGaussianBlur`** — 모양을 그린 뒤 그 «모양 자체»를 흐린다.

```
mask.feather === 0  → clip-path: path(...)         (가장 싸다)
mask.feather  > 0   → mask-image: url(#maskpath-<clipId>)   ← SVG <mask> 참조
```

### luminance 냐 alpha 냐 — 판단이 필요했던 지점

| | luminance (SVG `<mask>` 기본) | **alpha (권장)** |
|---|---|---|
| 무엇을 보나 | 마스크 그림의 **밝기** (흰=보임, 검=가림) | 마스크 그림의 **투명도** |
| 배경 | **검은 사각형을 반드시 깔아야** 한다 | 필요 없다 |
| 블러하면 | 흰 도형이 «투명한 검정»으로 번져 프리멀티플라이 때문에 **경계가 어두워진다** | 알파만 번진다. 깔끔 |
| 기존 마스크 3종과 | **다르다** — 지금은 `#fff`/`transparent` 그라디언트 = 알파 방식 | **같다** |
| CSS 로 지정 | `mask-type="luminance"` | `<mask mask-type="alpha">` |

**alpha 를 쓴다.** 결정적인 이유는 마지막 줄이다 — `maskStyle()`(`clips.tsx:61-87`)이
`linear-gradient(#fff → transparent)` 를 쓰고 있어 **기존 3종은 이미 알파 마스크**다.
여기서 luminance 를 섞으면 같은 `feather: 0.3` 이 모양에 따라 다른 두께로 보인다.

**함께 반드시 지정할 것:**

```xml
<mask id="…" mask-type="alpha" maskUnits="userSpaceOnUse"
      x="0" y="0" width="{boxW}" height="{boxH}">
  <filter id="…f" color-interpolation-filters="sRGB"
          x="-20%" y="-20%" width="140%" height="140%">
    <feGaussianBlur stdDeviation="{feather * min(boxW,boxH) / 2}" />
  </filter>
  <path d="…" fill="#fff" filter="url(#…f)" />
</mask>
```

- **`color-interpolation-filters="sRGB"`** — SVG 필터의 기본값은 `linearRGB` 이고, 그러면
  페더의 밝기 곡선이 달라진다. `ClipFilterDefs`(`svg-filters.tsx:224`)가 이미 같은 이유로
  이 속성을 넣고 있다. **빠뜨리면 페더만 다른 감쇠로 보인다.**
- **`maskUnits="userSpaceOnUse"` + 명시적 x/y/width/height** — 기본값은
  `objectBoundingBox` 의 −10%..110% 인데, `ClipFilterDefs` 가 쓰는 컨테이너가
  **`<svg width="0" height="0">`**(`svg-filters.tsx:221`)이라 좌표계가 0이다.
  기본값으로 두면 마스크 내용이 잘려 **아무것도 안 보이거나 전부 보인다.**
- 필터 영역을 `-20%..140%` 로 넓히지 않으면 **번진 가장자리가 잘린다**(기본은 −10%..110%,
  큰 페더에서 부족).

## 스키마 변경 (전부 optional)

```ts
export type MaskOp = 'add' | 'subtract' | 'intersect';

export type Mask = {
  shape: 'rect' | 'circle' | 'linear' | 'path';   // ← 'path' 추가
  feather: number;          // 0..1
  invert?: boolean;
  x: number; y: number; w: number; h: number;     // 마스크 상자 (클립 상자 대비 0..1)
  d?: string;               // shape==='path' 일 때 필수. 좌표는 «마스크 상자» 안의 0..1
  op?: MaskOp;              // masks[] 안에서만 의미. 기본 'add'
  dKeys?: MaskShapeKey[];   // 모양 자체의 키프레임 (아래 §모양 애니메이션)
};

export type MaskShapeKey = { time: number; d: string; easing?: Easing };

// VideoClip / ImageClip
mask?: Mask;                // 기존 (그대로 유효)
masks?: Mask[];             // ← 신규. 있으면 mask 는 무시된다
```

### `d` 의 좌표계 — 여기가 설계의 핵심이다

**`d` 는 「마스크 상자 안의 0..1」이다.** 클립 상자가 아니라 `(x, y, w, h)` 가 정한 상자 안이다.

```
최종 px = ( x + dx·w ) · boxW ,  ( y + dy·h ) · boxH
```

이렇게 하면 **모양은 `d` 가, 위치·크기는 `x/y/w/h` 가** 담당한다. 얻는 것:

1. **F10 마스크 트래킹이 공짜로 붙는다.** 트래킹은 `mask.x/y/w/h` 에 키프레임을 넣는데,
   그게 곧 「그린 모양을 대상 따라 옮기고 키우기」가 된다. `d` 는 손댈 필요가 없다.
2. **해상도 독립.** 1080p 로 그린 마스크가 4K 에서도 같은 자리다.
3. **기존 3종과 규칙이 같다** — `x/y/w/h` 의 의미가 도형 종류와 무관하게 하나다.

### `d` 검증 — 문법 제한 + **CSS 주입 차단**

`d` 는 `clip-path: path("…")` 라는 **CSS 문자열 안에 그대로 들어간다.**
따옴표 하나가 들어가면 그 자리에서 CSS 를 빠져나가 임의의 속성을 쓸 수 있다.

```ts
const PATH_D_RE = /^[MmLlCcQqZz0-9eE ,.+-]+$/;   // 허용 문자만. 따옴표·괄호·백슬래시 없음
// 길이 상한 4000자, 명령 개수 상한 500
```

- **허용 명령: `M L C Q Z` 와 소문자판만.** 펜 툴이 만드는 것은 이게 전부다.
  `A`(호)는 플래그 인자가 있어 파서가 복잡해지고, 원은 `C` 4개로 충분히 근사된다.
- **`H V S T` 도 뺀다** — 축약형은 파서만 늘리고 펜 툴이 만들지 않는다.
- 숫자는 전부 유한값이어야 한다(`NaN`·`Infinity` 문자열 거부).

## 모양 자체의 애니메이션 — S1 로는 안 된다 (중요한 발견)

**`Keyframe.value` 는 `number` 다.** 그래서 S1(경로 키프레임)으로는 `mask.d` 에 키프레임을
걸 수 없다. 문자열을 넣을 자리가 없다. 두 갈래가 있다.

| | **(A) `dKeys` — 채택** | (B) 정점마다 S1 키프레임 |
|---|---|---|
| 방식 | `{time, d, easing}` 목록. `interpolatePath` 로 보간 | `mask.pts[3].x` 같은 경로 40~70개 |
| 새 메커니즘 | 필요 (약 40줄) | **없음** — S1 그대로 |
| 문서 크기 | 키당 `d` 문자열 1개 | 정점 12개면 경로 **최대 72개** |
| UI | 펜 툴이 통째로 커밋 → 자연스럽다 | 키프레임 표에 72줄 |
| 정점 개수 변경 | **불가**(아래 제약) | 가능 |
| 정점별 다른 이징 | 불가 | 가능 |

**(A)로 간다.** 펜 툴은 모양을 «통째로» 편집하는 도구이므로 키도 통째가 맞다.
(B)는 쓸 수 있지만 키프레임 표를 못 쓰게 만든다.

**⚠️ `interpolatePath` 의 제약 — 확인 필요:**
두 path 의 **명령 구성이 같아야** 보간된다(`M C C C Z` ↔ `M C C C Z`). 즉 키프레임 사이에서
**정점을 추가·삭제할 수 없다.** UI 는 `dKeys` 가 2개 이상일 때 정점 추가/삭제 버튼을 잠그고
「모양 키프레임이 있는 동안에는 점을 더하거나 뺄 수 없습니다」를 표시한다.
**확인 방법:** 명령 수가 다른 두 path 를 `interpolatePath` 에 넣어 던지는지 / 조용히
이상한 값을 내는지 실제로 돌려 본다. 조용히 이상하면 우리가 먼저 막아야 한다.

`@remotion/paths` 는 **4.0.520 이라 버전 일괄 상향이 선행**된다 — 08-kinetic-type.md §5 와
같은 선행 조건이고, 두 작업이 이 상향을 공유한다.

### `@remotion/paths` 로 얻는 것

| 함수 | 어디에 쓰나 |
|---|---|
| `getBoundingBox(d)` | 그린 모양의 실제 범위 → `x/y/w/h` 를 **자동으로 꽉 맞게** 잡아 준다 |
| `getPointAtLength(d, l)` | 펜 툴에서 선 위를 클릭했을 때 **그 자리에 점 삽입** |
| `getSubpaths(d)` | 여러 조각(구멍 뚫린 마스크)을 나눠 다룬다 |
| `interpolatePath(t, a, b)` | `dKeys` 보간 |
| `reversePath(d)` | 반전·`evenodd` 방향 맞추기 |

**전부 순수 계산이라 렌더 없이도 쓸 수 있다** — UI 에서 먼저 쓰고 렌더는 결과만 받는다.

## 여러 마스크 겹치기와 반전

### `masks[]` + `mask-composite`

CSS 는 마스크 레이어를 여러 장 쌓고 합성 방식을 지정할 수 있다.
**이 저장소는 이미 그 기법을 쓰고 있다** — 사각 마스크가 가로·세로 그라디언트 2장을
`maskComposite: 'intersect'` 로 교차시킨다(`clips.tsx:81-86`). 새 개념이 아니다.

| `op` | CSS `mask-composite` | `-webkit-mask-composite` (구형) | 뜻 |
|---|---|---|---|
| `add` (기본) | `add` | `source-over` | 합집합 — 둘 중 하나라도 보이면 보임 |
| `subtract` | `subtract` | `source-out` | 앞의 결과에서 이 모양을 **판다** |
| `intersect` | `intersect` | `source-in` | 교집합 |

첫 레이어의 `op` 는 무시된다(합성할 대상이 없다). 순서는 배열 순서다.

**`clip-path` 는 하나뿐이다** — `masks.length >= 2` 면 페더가 0이어도 **전부 `mask-image` 경로**로
간다. 그 경우 각 레이어는 SVG `<mask>` 하나씩이거나, 페더 0인 레이어는
`url("data:image/svg+xml,…")` 대신 **하나의 `<mask>` 안에 여러 `<path>`** 로 합친다
(레이어를 늘리는 것보다 싸고, `subtract` 는 `<path fill="#000">` 로 그리면 알파가 지워진다).
→ **구현은 `<mask>` 하나에 path 여러 개.** `mask-composite` 는 결국 안 쓰게 되지만
기존 3종과 섞일 때(그라디언트 레이어 + path 레이어)를 위해 경로는 남긴다.

### 반전

| 경로 | 반전 방법 |
|---|---|
| `clip-path` | 바깥 사각형을 앞에 두고 `path(evenodd, "M0,0 H{W} V{H} H0 Z {원래 d}")` |
| SVG `<mask>` | 흰 사각형을 깔고 원래 모양을 **검정으로** 그린다 (alpha 마스크에서는 `fill-opacity="0"` 이 아니라 사각형→도형 순서로 `feComposite operator="out"`) |

기존 3종의 `invert` 는 그라디언트 색을 뒤집는 방식이다(`clips.tsx:62-63`) — 그대로 둔다.

## 빠른 미리보기(WebGL)는 어떻게 그리나

`packages/ui/src/preview/gl.ts:401` 이 지금 마스크를 **「마스크(미지원)」 배지**로 처리한다.
F15 가 rect/circle/linear 를 셰이더의 거리 함수로 구현하기로 되어 있는데,
**자유 path 는 거리 함수로 못 쓴다.**

**→ 래스터화해서 텍스처로 올린다.**

```
1. Canvas2D: new Path2D(pxD) → ctx.fill()   ← 브라우저가 같은 path 엔진으로 그린다
2. feather > 0 이면 ctx.filter = `blur(${σ}px)`  (Canvas2D 필터, Chromium 지원)
3. 결과 캔버스를 gl.texImage2D 로 알파 텍스처로 업로드
4. 셰이더에서 곱한다
```

- **키는 `(d, boxW, boxH, feather)`** — 이게 안 바뀌면 재래스터화하지 않는다.
  마스크가 움직이기만 하면(`x/y` 키프레임) `d` 와 상자 크기가 그대로라 **텍스처를 재사용**하고
  UV 만 민다. 트래킹 재생 중에도 매 프레임 그리지 않는다.
- 브라우저의 `Path2D` 채우기 규칙이 SVG `<path>` 와 같으므로 **렌더와 어긋날 이유가 구조적으로 없다.**
- 이건 F15 의 `PassChain` 과 독립이다(패스가 안 늘어난다). **다만 F15 계획에 이 항목을
  추가해야 한다** — 15-preview-parity.md 의 표 1번 「마스크」는 지금 3종만 상정하고 있다.

## UI — 여기가 진짜 일이다

### 어디에 뜨나

`VideoSection` 의 마스크 켜기 옆에 **[모양 그리기]** 버튼. 누르면 **미리보기 화면 위에
편집 오버레이**가 뜨고 재생이 멈춘다. 인스펙터의 숫자 필드로는 자유 곡선을 못 그린다.

### 좌표 변환 — 가장 틀리기 쉬운 곳

포인터는 **화면 CSS px** 에 있고, 마스크는 **클립 상자의 로컬 좌표**에 산다.
그 사이에 **클립의 `transform: scale(...) rotate(...)`** 가 끼어 있다(`clips.tsx:136`).

```
화면 px
  → (미리보기 캔버스의 표시 배율로 나눔)      → 캔버스 px
  → (layout.box.left/top 을 뺌)               → 상자 기준 px …이 아니다!
  → rotate(-rotationDeg) · scale(1/scaleX, 1/scaleY) 를 «상자 중심 기준»으로 역적용
  → 상자 로컬 px
  → (boxW, boxH 로 나눔)                       → 클립 상자 0..1
  → ((v - x) / w) 로 마스크 상자로 옮김        → d 의 0..1
```

**회전한 클립 위에서 펜 툴이 어긋나면 이 역변환이 원인이다.** 역변환 함수를
`packages/renderer/src/layout/index.ts` 에 **정변환과 나란히** 둔다
(`maskLocalFromCanvas(layout, px, py)`) — UI 가 자기 식으로 다시 계산하면 갈린다.

| 점 선택 후 `Delete` | 삭제 |
| 방향키 / `Shift`+방향키 | 1px / 10px 이동 |
| `Ctrl+Z` / `Ctrl+Shift+Z` | **편집기 안의** 되돌리기 |
| `Esc` | 편집 취소(문서를 안 건드리고 나감) |
| `Enter` 또는 [적용] | 문서에 커밋 |

### 되돌리기를 두 층으로 나누는 이유

펜 툴은 드래그 한 번에 좌표가 수백 번 바뀐다. 그걸 전부 `updateClip` 명령으로 보내면
**명령 로그가 터지고 문서 되돌리기가 쓸모없어진다**(한 번 누를 때마다 1px 씩 되돌아간다).

→ **편집기가 자기 스택을 갖는다**(메모리 안, 최대 100단계). 문서에는
`CurvesSection` 과 같은 **200ms 디바운스**(`useDebouncedCommit`, `fields.tsx`)로 나가고,
편집을 끝내면 한 번 더 커밋한다. **문서 되돌리기 1회 = 「마스크 모양 편집」 1건.**

### 저장 형태 — `d` 하나만

편집기 내부 모델은 `{ pts: {x, y, hIn?, hOut?}[], closed }` 지만 **문서에는 `d` 만 저장한다.**
다시 열 때는 `d` 를 파싱해 정점·핸들을 복원한다. 우리 문법이 `M L C Q Z` 5개뿐이라
파서가 **약 60줄**이다.

정점 모델을 따로 저장하면 `d` 와 어긋날 수 있는 두 번째 진실이 생긴다. 그게 더 비싸다.

### 보조

- **[모양에 맞추기]** 버튼 — `getBoundingBox(d)` 로 `x/y/w/h` 를 꽉 맞게 다시 잡는다
  (트래킹이 잘 먹으려면 상자가 모양에 붙어 있어야 한다)
- 편집 중 **격자·스냅**(격자 20px, `Ctrl` 로 일시 해제)
- 편집 중에도 **페더 슬라이더가 실시간 반영**된다 — 페더는 모양 확정 전에 봐야 정할 수 있다
- 정점 수 표시(`12점`) — `dKeys` 가 있을 때 왜 잠겼는지 이해하게

## 확인 필요 — `mask` + `mixBlendMode` + 부모 `transform`

W7 조사가 **확신 못 한 것**으로 남긴 항목이다:

> `mask: url(#id)` 가 `mixBlendMode`·부모 `transform` 과 겹칠 때 Chromium 좌표계가 어긋나는
> 케이스가 있는지 확인 못 했다.

**지금 코드는 셋을 정확히 같은 요소에 건다** (`clips.tsx:129-150`):

```ts
const boxStyle = {
  left, top, width, height,
  transform: `scale(${layout.scaleX}, ${layout.scaleY}) rotate(${layout.rotationDeg}deg)`,
  ...(layout.blendMode ? { mixBlendMode: layout.blendMode } : {}),
  ...(layout.mask ? maskStyle(layout.mask) : {}),
};
```

규격상의 순서는 「그리기 → 필터 → 클립/마스크 → 불투명도 → 블렌드」이므로 **마스크가 먼저,
블렌드가 나중**이 맞고, `transform` 은 마스크까지 포함한 결과 전체에 걸린다(=마스크가 클립과
함께 돈다). **이론상 맞다. 하지만 확인하지 않았다.**

**확인 방법 (그대로 실행):**

1. 1080×1920 테스트 클립 — 흰 배경 위 검은 사각형
2. 조합 8가지: `{path 마스크, rect 마스크} × {rotation 0°, 30°} × {mixBlendMode 없음, screen}`
3. 각각을 (a) `renderStill` (b) 빠른 미리보기 캡처로 뽑는다
4. **마스크 경계의 실제 화면 좌표**를 픽셀에서 찾아 기하학적 기댓값과 비교 —
   **합격: ±2px**
5. (a)와 (b)의 픽셀 차이 — **평균 ≤ 3, 최대 ≤ 12**

어긋나는 조합이 나오면 **마스크를 `boxStyle` 에서 떼어 안쪽 래퍼 하나로 내린다**
(`TransitionWrappers` 가 이미 쓰는 방식이다 — `clips.tsx:101-110`).
어긋난 조합과 수치를 문서에 남긴다.

**같이 확인할 것 — `<mask>` 안의 필터 단위:**
`maskContentUnits="objectBoundingBox"` 를 쓰면 `d` 를 px 로 바꿀 필요조차 없어 매력적이지만,
그 안의 `<filter>` 의 `stdDeviation` 이 어떤 단위로 해석되는지가 브라우저마다 미묘하다.
→ **`userSpaceOnUse` + px 변환으로 먼저 만들고**, `objectBoundingBox` 는
같은 테스트로 결과가 동일할 때만 「더 단순한 길」로 교체한다. 확인 전에 바꾸지 않는다.

## 검증 — 숫자로 낸다

**1. 기존 3종 회귀**
rect·circle·linear 마스크가 든 프로젝트를 렌더 → 변경 전과 **픽셀 완전 일치**(PSNR = ∞).

**2. 하드 엣지 정확도**
정삼각형 path 마스크(꼭짓점 좌표 계산 가능)를 1080×1920 에 걸고 렌더.
**꼭짓점 3개의 실측 위치가 기댓값과 ±1px.** 변의 기울기도 ±1px.

**3. 페더**
`feather` 0 / 0.1 / 0.3 / 0.6 각각에서 경계를 가로지르는 픽셀 줄의 알파 프로파일을 뽑는다.
- **10%→90% 전이 폭**이 `feather × min(boxW, boxH) × k` 에 **±15%** 이내로 비례
- **단조 감소** (중간에 다시 올라가면 프리멀티플라이 문제 — luminance 로 잘못 갔다는 신호)
- `sRGB` 지정을 뺐을 때와 비교해 **실제로 다른지** 확인하고 그 차이를 문서에 적는다
  (「빠뜨리면 안 된다」의 근거)

**4. 여러 마스크**
`add` / `subtract` / `intersect` 3종을 원+사각 조합으로 렌더해 **보이는 픽셀 수**를 센다.
- `add` = 합집합 넓이, `intersect` = 교집합 넓이, `subtract` = 원 넓이 − 교집합
- **오차 ≤ 1%** (안티에일리어싱 여유)

**5. 반전**
같은 마스크의 `invert: false` / `true` 결과를 더하면 **전체가 정확히 채워져야** 한다 —
알파 합이 모든 픽셀에서 `1.0 ± 0.01`.

**6. `d` 검증**
| 입력 | 기대 |
|---|---|
| `M 0,0 L 1,0 L 1,1 Z` | 통과 |
| `M 0,0 A 1 1 0 0 1 1,1` (호) | **거부** |
| `M 0,0 L 1,0") ; background:url(evil` | **거부** (주입 시도) |
| 5000자 | **거부** (길이 상한) |
| `M 0,0 L NaN,0` | **거부** |

**7. 미리보기 ↔ 렌더**
path 마스크 × 페더 4단계 × 회전 2가지 = 8케이스에서
**평균 채널 차이 ≤ 3, 최대 ≤ 12.** 넘으면 수치를 그대로 적는다.

**8. 모양 키프레임**
정점 수가 같은 두 모양 사이의 `dKeys` 보간을 t=0/0.5/1 에서 렌더해
**보이는 픽셀 수가 단조 변화**하고, t=0·1 이 각 키의 정적 결과와 **픽셀 완전 일치**.
정점 수가 다른 두 모양을 넣으면 **`BAD_MASK` 로 거부**되는지.

**9. 성능**
- 렌더: path 마스크(페더 0.3)가 걸린 30초 클립의 렌더 시간을 rect 마스크 대비 측정.
  **20% 이상 느려지면** 필터 영역·해상도를 다시 본다
- 미리보기: 마스크 텍스처 캐시가 **실제로 재사용되는지** — `x` 키프레임으로 마스크만
  움직일 때 래스터화 호출 수가 **1회**여야 한다 (900프레임 재생 중)

**10. 펜 툴 좌표**
회전 0° / 30° / −45°, 배율 0.5× / 1× / 2× 의 9조합에서 **화면의 같은 지점을 클릭**했을 때
찍히는 점이 그 지점에 오는지 — **±2px.** 이게 편집기의 유일한 정답 조건이다.

## 하지 않을 것

- **「페더는 clip-path 로 안 되니 페더 없이」로 축소하지 않는다.** SVG `<mask>` 로 한다.
  페더 없는 마스크는 합성 티가 나서 광고에 못 쓴다.
- **`A`(호) 명령을 「나중에」로 미루면서 원형 자유 마스크를 못 그리게 두지 않는다.**
  펜 툴이 `C` 4개로 원을 만든다(오차 0.03%).
- **정점 모델을 문서에 따로 저장하지 않는다.** `d` 를 파싱한다.
- **드래그마다 `updateClip` 을 보내지 않는다.** 문서 되돌리기가 쓸모없어진다.
- **회전한 클립에서 좌표가 어긋나는 것을 「알려진 제약」으로 적고 넘어가지 않는다.**
  §확인 필요의 8조합을 실제로 재고, 어긋나면 마스크를 안쪽 래퍼로 내린다.
- **빠른 미리보기에서 자유 마스크를 「미지원 배지」로 두지 않는다.** 래스터화 경로가 있다.
  15-preview-parity.md 가 배지를 없애기로 한 것과 같은 이유다.
