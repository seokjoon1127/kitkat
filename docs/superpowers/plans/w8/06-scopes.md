# F6. 스코프 — 실시간 + 정밀 (고해성사 #6)

## 무엇을 잘못했나

W7 조사에 이렇게 썼다:

> 재생 중에는 못 쓴다(스틸 렌더가 1~2초). 색보정은 멈춰서 하는 작업이라 문제없다.

**「서버가 스틸을 렌더한다」는 내 설계를 전제로 「그러니 실시간은 불가」라고 단정했다.**
그런데 **빠른 미리보기에 이미 WebGL 캔버스가 있고 `gl.readPixels()` 로 픽셀을 읽을 수 있다.**
브라우저에서 실시간 스코프가 가능한데 확인도 안 하고 못 한다고 썼다.

「색보정은 멈춰서 하는 작업」이라는 것도 내 추측이다. **실제 콜리스트는 재생하면서 스코프를 본다.**
컷이 넘어갈 때 웨이브폼이 어떻게 튀는지가 컷별 색 맞추기의 핵심 정보다.

## 두 가지를 다 만든다

| | 실시간 스코프 | 정밀 스코프 |
|---|---|---|
| 출처 | 브라우저 WebGL 캔버스 `readPixels` | 서버가 렌더한 스틸 + ffmpeg |
| 지연 | 프레임당 (재생 중에도) | 1~2초 |
| 정확도 | 미리보기 기준 (프록시·근사 포함) | **최종 렌더와 동일** |
| 용도 | 훑어보기·컷 비교·재생 중 감시 | 최종 확인·수치 판정 |

**둘 다 필요하다.** 실시간만 있으면 프록시의 색을 믿게 되고, 정밀만 있으면 재생 중에 못 본다.
UI 는 스코프 패널에 **「미리보기 기준」/「최종 렌더 기준」 배지**를 항상 표시한다.

## A. 실시간 스코프 (브라우저)

### 어디서 픽셀을 얻나
`packages/ui/src/preview/gl.ts` 의 `GlCompositor` 가 이미 1080×1920 캔버스에 합성한다.
→ 합성 직후 **다운샘플해서** 읽는다. 전체 해상도를 매 프레임 읽으면 GPU 파이프라인이 멈춘다.

```ts
// packages/ui/src/preview/scope-source.ts (신규)
/** 합성 결과를 작은 해상도로 축소해 읽는다. 기본 256×455(세로 기준). */
export function readScopeSample(gl: WebGL2RenderingContext, w: number, h: number): Uint8Array;
```

**성능 주의 3가지:**
1. `readPixels` 는 **동기라 GPU 를 멈춘다.** → **PBO(Pixel Buffer Object) 비동기 읽기**를 쓴다
   (`gl.readPixels` 를 `PIXEL_PACK_BUFFER` 에 걸고 다음 프레임에 `getBufferSubData`).
   WebGL2 에서만 되는데 우리는 WebGL2 다.
2. **매 프레임 읽지 않는다** — 기본 5프레임에 1회(6fps). 스코프는 그 정도면 충분하다.
3. 축소는 **셰이더로** 한다(밉맵 또는 별도 패스). CPU 축소는 느리다.

### 스코프 계산 — 웹워커
읽은 픽셀(256×455 ≈ 116k)로 3종을 계산한다. **메인 스레드를 막지 않도록 Worker 에서.**

```ts
// packages/ui/src/preview/scopes.worker.ts (신규)
// 입력: Uint8Array(RGBA) + 종류 → 출력: ImageBitmap (transferable)
```

**웨이브폼(RGB 퍼레이드)** — 가로 x 마다 세로로 밝기 분포. 출력 캔버스의 `(x, 255-v)` 픽셀에
누적 가산 후 감마 보정. R·G·B 를 가로로 3등분해 나란히.

**벡터스코프** — 각 픽셀의 `(Cb, Cr)` 을 극좌표에 찍는다.
`Cb = -0.169R -0.331G +0.500B`, `Cr = 0.500R -0.419G -0.081B` (BT.601).
**스킨톤 라인(약 33°)** 과 6색 타깃(R/Mg/B/Cy/G/Yl) 격자를 겹쳐 그린다 — 이게 있어야 쓸모가 있다.

**히스토그램** — R·G·B 각 256빈 카운트. 로그 스케일 옵션.

### UI
인스펙터 옆 또는 플레이어 아래에 접이식 패널. 3종을 탭 또는 나란히.
**클립 두 개를 「비교」로 고정**해 두 스코프를 위아래로 볼 수 있게 한다 — 컷별 색 맞추기(F4)의 짝이다.

## B. 정밀 스코프 (서버)

### API
```
POST /api/projects/:id/scopes
  { timeMs: number, kinds: ('waveform'|'vectorscope'|'histogram')[], proxy?: boolean }
→ { jobId }   // 완료 시 result.urls = { waveform: '/media/scopes/...png', ... }
```

### 구현 (검증된 명령 — 2026-09-02 실행 확인)
1. `renderStill`(기존 `renderCover` 경로)로 `timeMs` 의 스틸 PNG
2. 그 PNG 에 ffmpeg 필터:
```
waveform=intensity=0.2:mirror=1:components=7:display=overlay
vectorscope=mode=color3:graticule=green:flags=name
histogram=display_mode=stack:levels_mode=logarithmic
```
3. `media/scopes/<projectId>-<timeMs>-<kind>.png`

**캐시**: 같은 (project revision, timeMs, kind) 면 재사용. revision 이 오르면 무효화.

### 왜 서버 쪽도 필요한가
미리보기는 **540p 프록시**를 쓰고 빠른 미리보기는 일부 효과를 근사한다.
**색을 수치로 판정하려면 최종 렌더와 같은 픽셀이어야 한다.** 그게 정밀 스코프의 존재 이유다.

## 검증

**정확도** — 알려진 신호로 대조한다:
- 100% 컬러바 → 벡터스코프의 6개 점이 **격자 타깃 안**에 들어가야 한다
- 0~100% 그레이 램프 → 웨이브폼이 **직선**이어야 한다
- 순수 흰색/검정 → 히스토그램이 양 끝에 스파이크

**실시간 vs 정밀 일치** — 같은 프레임을 두 경로로 측정해 **평균 밝기·색차 차이가 임계 안**인지.
차이가 크면 그건 프록시/근사 탓이므로, **얼마나 다른지를 수치로 문서에 적는다**(사용자가 알아야 한다).

**성능** — 실시간 스코프를 켠 상태의 재생 fps 를 껐을 때와 비교. **10% 이상 떨어지면 실패**로 보고
샘플 해상도·주기를 조정한다.

**Worker 격리** — 스코프 계산 중 메인 스레드 블로킹이 없는지(long task 측정).

## 하지 않을 것
- **「멈춰서 보는 것」으로 축소하지 않는다.** 재생 중에 보여야 한다.
- 실시간이 부정확하다는 이유로 안 만들지 않는다. **부정확한 정도를 표시하고 둘 다 준다.**
