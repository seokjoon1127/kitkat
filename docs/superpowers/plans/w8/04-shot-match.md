# F4. 컷별 색 맞추기 (W7 조사 #1)

## 무엇을 하나

AI 로 만든 영상은 컷마다 색이 제각각이다. 같은 사람인데 2번 컷은 노랗고 3번 컷은 파랗다.
**기준 컷 하나를 정하고 나머지 컷의 색을 거기에 맞춘다.** 방법은 RGB 채널마다 평균(밝기 중심)과
표준편차(대비 폭)를 재서, 대상 컷의 통계를 기준 컷의 통계로 옮기는 1차식을 만들고 ffmpeg
`colorlevels` 로 굽는 것이다. 파생 미디어(M2)에 들어가므로 LUT·손떨림 보정과 같은 자리다.

**W7 실측 (2026-09-02, 이 컴퓨터)** — 같은 장면을 「따뜻·밝음」/「차갑·어두움」으로 갈라 놓고 맞춤:

```
채널   기준 컷        대상 컷        →  맞춘 뒤 기준과의 차이
R    119.3±117.5   103.7±102.0   →  15.7 → 0.4
G    131.9±120.3    93.0± 89.2   →  38.9 → 4.3
B    126.8±126.3    71.3± 66.1   →  55.5 → 1.6
                          합계 110.1 → 6.3  (94% 감소)
```

**한계도 실측됐다: 내용이 다른 두 컷에서는 80% 감소에 그쳤고 과보정이 난다.** 내용이 다르면
색 통계가 다른 게 정상인데 억지로 맞추기 때문이다. 그래서 **강도 슬라이더**와 **기준 영역 지정**이
장식이 아니라 필수다. 아래에서 둘 다 설계한다.

## 스키마

S3 가 정의한 것에 **`refRegion` 과 `levels` 두 칸을 더한다** (둘 다 optional — S3 를 깨지 않는다).

```ts
// packages/schema/src/index.ts — ClipSource 안
matchTo?: {
  clipId: string;          // 기준 클립 id
  strength: number;        // 0..1, 기본 1
  region?: Crop;           // «대상» 클립에서 비교할 영역 (0..1 정규화). 없으면 clip.crop, 그것도 없으면 전체
  refRegion?: Crop;        // «기준» 클립에서 비교할 영역. 없으면 기준 클립의 crop, 그것도 없으면 전체
  levels?: MatchLevels;    // 측정 결과 캐시 (아래)
};

export type MatchLevels = {
  /** 측정 시각(ms, 소스 기준)들 — 재현·감사용 */
  sampledAtMs: number[];
  /** 기준 클립의 sourceKey (또는 'raw') — 기준이 바뀐 것을 감지하는 데 쓴다 */
  refSourceKey: string;
  /** 채널별 μ·σ (0..1). r/g/b 순서 고정 */
  ref: [ChannelStat, ChannelStat, ChannelStat];
  target: [ChannelStat, ChannelStat, ChannelStat];
};
export type ChannelStat = { mean: number; std: number };
```

### 왜 `levels` 를 문서에 캐시하나 — 판단이 필요했던 곳

두 가지 설계가 있었다.

| | (a) 굽기 직전에 서버가 측정 | (b) 측정을 따로 돌리고 결과를 문서에 |
|---|---|---|
| `sourceKey` | 기준 클립의 identity 까지 넣어야 해 **`sourceKey(clip)` 이 doc 을 받아야 한다** | 클립 하나로 닫힌다 |
| 재현성 | 같은 문서라도 기준 클립을 만지면 결과가 달라진다 | 같은 문서 = 같은 결과 |
| 기준 클립 삭제 | 파생이 깨진다 | 이미 맞춘 결과는 그대로 |
| 사용자가 값을 볼 수 있나 | 못 본다 | 인스펙터에 숫자로 보인다 |

**(b) 를 쓴다.** (a) 는 S3 의 「`sourceKey` 는 클립의 `source` 만 해시한다」는 계약을 깨고, 굽기가
언제 도느냐에 따라 결과가 달라진다.

(b) 의 대가: **기준 클립을 나중에 색보정하면 자동으로 다시 안 맞춰진다.** 그래서 `refSourceKey` 를
같이 저장하고, 지금 기준 클립의 `sourceKey` 와 다르면 인스펙터에 **「기준 컷이 바뀌었습니다 —
다시 재기」** 배지를 띄운다. 조용히 옛 값을 쓰지 않는다.

`sourceKey` 에는 `matchTo` 의 **모든 필드**를 넣는다 — `clipId` · `strength` · `region` 4값 ·
`refRegion` 4값 · `levels` 의 12개 μ·σ 전부. 하나라도 빠뜨리면 다른 설정인데 같은 파일을 쓴다.

## 통계를 어디서 재나

### 어느 프레임? — 균등 간격 5장, 픽셀을 다 합쳐서 한 번에

- **한 장은 안 된다.** 그 프레임에 우연히 큰 빨간 물체가 지나가면 통계가 통째로 튄다.
- **클립 «중앙 한 장」도 안 된다.** 컷 안에서 조명이 변하는 경우(창가로 걸어가는 인물)를 못 잡는다.
- → **클립의 `in`~`out` 구간을 균등 간격으로 5장** 뽑는다. 단 **양 끝 5%는 잘라낸다** — 소스 자체에
  페이드가 걸려 있으면 그 프레임은 색이 다른 화면이다.
  - 5장의 시각: `in + (out−in)·(0.05 + 0.9·k/4)`, k=0..4.
- **프레임별로 평균을 낸 뒤 다시 평균하지 않는다.** 5장의 픽셀을 **전부 한 통에 넣고** μ·σ 를 한 번
  계산한다. 프레임별 평균의 평균은 σ 를 과소평가한다(프레임 간 변동이 사라진다).
- **5장인 근거는 아직 없다.** 「검증」에서 1장·5장·20장의 결과 차이를 재고, 5장이 20장 대비 채널
  평균 차 2/255 이내면 5장으로 확정한다. 아니면 늘린다. **지금은 5로 시작하고 재서 정한다.**

### 어느 파일에서?

| | 어디서 재나 | 왜 |
|---|---|---|
| **기준 클립** | 파생 파일이 있으면 **그것**(`asset.derived[key].src`), 없으면 원본 | 기준 컷은 「이 색으로 맞춰라」다. LUT 를 먹인 컷을 기준으로 골랐으면 **사용자가 보는 그 색**이 기준이어야 한다 |
| **대상 클립** | **원본** (matchTo 직전 상태) | S3 의 필터 순서가 `stabilize → matchTo → hsl → lut` 이라 matchTo 는 원본 위에서 계산된다 |

**⚠️ 확인 필요:** 대상 클립에 `stabilize` 가 걸려 있으면 `vidstabtransform` 이 프레임을 확대하고
가장자리를 채운다 — 색 통계가 달라질 수 있다. 확인 방법: 같은 소스를 stabilize 있음/없음으로 굽고
채널 μ·σ 를 비교한다. **차이가 1/255 를 넘으면 대상 측정도 stabilize 후 파일에서 해야 한다.**

### 영역

- `region`/`refRegion` 이 있으면 그 사각형만, 없으면 **클립의 `crop`**, 그것도 없으면 전체.
  - **`crop` 을 반영하는 이유:** 클립에 crop 이 걸려 있으면 화면에 나오는 건 crop 된 부분뿐이다.
    안 보이는 부분의 색을 맞출 이유가 없다.
- `region` 과 `refRegion` 이 **따로 필요한 이유**: 회색카드는 두 컷에서 같은 자리에 있을 수 있지만
  **피부는 인물이 화면 다른 데 있다.** 하나만 두면 실무에서 제일 중요한 「피부톤 맞추기」가 불가능해진다.

### 픽셀을 읽는 방법

`signalstats` 는 YUV 기준이라 RGB 채널별 μ·σ 를 안 준다. **rawvideo 로 받아 노드에서 직접 계산한다.**

```
ffmpeg -ss <t> -i <src> -frames:v 1 -vf "crop=<w>:<h>:<x>:<y>,format=rgb24" -f rawvideo -
```
`runFfmpegBuffer` 가 이미 있다. 1080×1920 5장 = 31MB — **축소하지 않는다.**
축소하면 이웃 픽셀 평균이 분산을 깎아 **σ 가 작아지고 대비 보정이 어긋난다.** 31MB 는 문제가 아니다.

```ts
// packages/media/src/match.ts (신규)
export type ChannelStat = { mean: number; std: number };
export async function measureRgbStats(absSrc: string, opts: {
  timesMs: number[];
  region?: { x: number; y: number; w: number; h: number };   // 0..1 정규화
}): Promise<[ChannelStat, ChannelStat, ChannelStat]>;
```

## colorlevels 로 옮기기 — 역산과 그 함정

채널마다 원하는 사상은 `out = a·in + b` (0..1 정규화):
```
a = σ_ref / σ_target
b = μ_ref − a·μ_target
```

**강도 `s` 적용:** `a_s = 1 + (a−1)·s`, `b_s = b·s`.
아핀 사상이라 **「사상을 보간」한 것과 「결과를 보간」한 것이 정확히 같다** —
`(1−s)·in + s·(a·in+b) = (1+(a−1)s)·in + s·b`. 그래서 s=0.5 는 진짜로 「절반만 맞추기」다.

**colorlevels 의 실제 파라미터 범위 (2026-09-02 `ffmpeg -h filter=colorlevels` 로 직접 확인):**
```
rimin/gimin/bimin, rimax/gimax/bimax : -1 .. 1
romin/gomin/bomin, romax/gomax/bomax :  0 .. 1
preserve : none(기본)|lum|max|avg|sum|nrm|pwr
```
`out = (in − imin)·(omax − omin)/(imax − imin) + omin`

**`preserve=none`(기본)을 쓴다.** `preserve=lum` 은 밝기를 보존하는데, 컷 맞추기는 밝기까지
맞추는 게 목적이라 켜면 안 된다.

### 역산 3단계

1. **이상적 파라미터**: `omin=0, omax=1, imin = −b/a, imax = (1−b)/a`.
   이러면 `out = (in + b/a)·a = a·in + b` 로 정확히 일치하고, 필터의 클리핑 지점도 원하는 사상의
   클리핑 지점과 같아진다.
2. **범위를 벗어나면 클램프하고 o 값을 다시 푼다**:
   `imin' = clamp(imin, −1, 1)`, `imax' = clamp(imax, −1, 1)`,
   `omin = clip01(a·imin' + b)`, `omax = clip01(a·imax' + b)`.
   (예: a=0.8, b=0.1 → imax=1.125 → 1, omin=0, omax=0.9 → 여전히 `0.8·in+0.1` 로 정확하다.)
3. **숫자로 확인한다.** 얻은 파라미터로 **입력 0..255 를 전부 넣어보고** `clip01(a·in+b)` 와 비교한다.
   **최대 오차가 1/255 를 넘으면 표현 불가**로 판정한다.

**표현 불가는 `a = σ_ref/σ_target` 이 0.5 미만일 때 나온다** (대상 컷의 대비가 기준의 2배 넘음 —
imin..imax 폭이 2를 넘어야 하는데 −1..1 이라 못 담는다). 이때 **조용히 클램프하지 않는다**:
잡을 실패시키고 「강도를 N% 이하로 낮추면 표현됩니다」를 계산해서 알려준다.
(s 를 낮추면 a→1 로 가므로 반드시 표현 가능해지는 s 가 존재한다 — 이분 탐색 20회면 찾는다.)

### 굽는 자리

`packages/media/src/derive.ts` — S3 의 순서 **2번**.
```ts
// DeriveSpec 확장
matchTo?: { levels: MatchLevels; strength: number };
```
`colorlevels=rimin=..:rimax=..:romin=..:romax=..:gimin=..:...:bomax=..`
`useLut`·`af` 와 **같은 패스**에 들어간다 — 패스가 늘지 않는다.

## 서버

### 측정 라우트 (신규)
```
POST /api/projects/:id/clips/:clipId/match-measure
  { refClipId: string, region?: Crop, refRegion?: Crop, strength?: number }
→ { jobId }
```
잡 타입 **`matchStats`** 를 `JobType` 에 추가. **fast 레인**(측정은 5프레임 디코드라 1초 안쪽),
타임아웃 10분.

잡이 하는 일:
1. 두 클립의 소스 절대경로와 샘플 시각 5개를 계산 (기준은 파생 파일 우선)
2. `measureRgbStats` 2회
3. `applyBatch` 로 `updateClip { source: { ...source, matchTo: { ..., levels } } }`
4. 결과에 **맞추기 전/후 예상 색차**를 담는다: `{ deltaBefore: 110.1, deltaAfter: 6.3 }`
   (후자는 사상을 통계에 적용한 예측값 — 실제 파생이 구워지면 그 파일로 다시 잴 수 있다)

이 `updateClip` 이 `source` 를 바꾸므로 **`scheduleDeriveJobs` 가 자동으로 굽기 잡을 만든다.**
측정 라우트가 굽기를 직접 부르지 않는다 — 기존 파생 스케줄러 하나만 남긴다.

### 엔진 검증
`doUpdateClip` 에서 `matchTo` 를 볼 때:
- `clipId` 가 **자기 자신**이면 `BAD_MATCH`
- `matchTo` 를 따라갔을 때 **순환**이면 `BAD_MATCH` (A→B→A)
- `strength` 가 0..1 밖이면 `BAD_MATCH`
- `region`/`refRegion` 의 `w`·`h` 가 0이면 `BAD_MATCH` (0픽셀 측정)

## 검증 — 숫자로 낸다

**1. W7 실측 재현** — 같은 장면 두 버전으로 채널 색차 합계 **110.1 → 6.3 이하**. 내용이 다른 두 컷은
**80% 이상 감소**. (재현이 안 되면 구현이 조사와 다른 것이므로 멈추고 원인을 찾는다.)

**2. 강도가 선형인지** — s=0 은 원본과 **픽셀 완전 동일**(PSNR ≥ 60dB). s=0.5 는 색차 감소량이
s=1.0 감소량의 **50% ± 5%p**. (아핀 보간이므로 이론상 정확히 절반이다.)

**3. 샘플 프레임 수** — 1장·5장·20장으로 각각 측정해 채널 μ·σ 를 비교. **5장이 20장 대비 μ 차
2/255 이내**면 5장 확정, 아니면 늘린다. 조명이 변하는 클립과 안 변하는 클립 둘 다에서 잰다.

**4. 표현 불가 검출** — 인위적으로 `σ_ref/σ_target = 0.3` 인 소스 쌍을 만들어 **잡이 실패하고**
「강도 N% 이하」 안내가 나오는지. 그 N 으로 다시 돌리면 성공하는지.

**5. 클리핑 손실** — 맞춘 결과의 히스토그램에서 **0과 255 에 몰린 픽셀 비율**을 원본과 비교.
`histogram=levels_mode=logarithmic` 또는 rawvideo 로 직접 센다. **5%p 넘게 늘면 인스펙터에 경고**
(「밝은 곳 3.2%가 뭉갰습니다 — 강도를 낮추거나 영역을 지정하세요」).

**6. stabilize 상호작용** (위 「확인 필요」) — stabilize 있음/없음의 채널 μ·σ 차이. 1/255 초과면
대상 측정 위치를 바꾼다.

**7. `sourceKey` 빠뜨림 검사** — `matchTo` 의 필드를 하나씩 바꿔 가며 **전부 다른 키**가 나오는지.
`levels` 안의 12개 숫자 각각도 포함.

**8. 필터 순서 근거** — 같은 클립에 `matchTo`+`lut` 을 걸고 순서를 바꿔 구운 두 파일의 픽셀 차이를
잰다. **다르다는 것을 확인**해야 S3 의 「색 맞추기가 LUT 보다 먼저」가 근거 있는 고정이 된다.

## 하지 않을 것

- **「내용이 다르면 부정확하니 같은 장면일 때만」 같은 제한을 걸지 않는다.** 부정확한 정도를
  숫자(색차 감소율·클리핑 비율)로 보여주고 사용자가 정한다.
- **강도 기본값을 낮게 잡아 「안전하게」 만들지 않는다.** 기본은 **1.0**(완전히 맞춤)이다.
  과보정은 경고와 스코프(F6)로 알린다.
- **측정이 실패했을 때 조용히 항등(아무것도 안 함)으로 넘어가지 않는다.** 잡을 실패시킨다.
- **colorlevels 로 표현 못 하는 조합을 클램프해서 「대충 비슷하게」 굽지 않는다.**
  1/255 를 넘으면 실패시키고 가능한 강도를 알려준다.
- **기준 컷이 바뀐 것을 무시하지 않는다.** `refSourceKey` 로 감지해서 배지를 띄운다.
- **자동으로 프로젝트 전체에 걸지 않는다.** 어떤 컷을 맞출지는 사용자가 고른다.
