# F5. HSL 세컨더리 (W7 조사 #2)

## 무엇을 하나

**화면 전체가 아니라 「빨간 것만」·「노란 것만」 골라서 색을 고친다.** 콜리스트가 세컨더리
(secondary) 라고 부르는 작업이고, 실제 용도의 대부분은 **피부톤 보정**이다 — AI 영상은 얼굴이
누렇거나 벌겋게 나오는데 화면 전체를 만지면 배경까지 같이 변한다.

**W7 실측 (2026-09-02)** — `selectivecolor=reds=0.35 0 -0.25 0` 을 컬러바에 걸었더니:

| 색 | 변화량 |
|---|---|
| 빨강 | **109** |
| 초록·파랑·청록·자홍·노랑 | **전부 정확히 0** |

색상 계열별로 정확히 분리된다. 「2번 컷의 피부톤만 3번 컷에 맞추기」가 이걸로 된다.
파생 미디어(M2) 한 패스에 들어가므로 렌더 시간이 늘지 않는다.

---

## 두 필터를 함께 쓴다 — 왜 하나로 안 되나

**2026-09-02 이 빌드에서 `ffmpeg -h filter=...` 로 직접 확인한 파라미터:**

```
selectivecolor  correction_method: absolute(기본)|relative
                reds yellows greens cyans blues magentas whites neutrals blacks
                → 각각 "C M Y K" 문자열 (각 -1..1)
huesaturation   hue: -180..180 · saturation: -1..1 · intensity: -1..1
                colors: r+y+g+c+b+m+a 플래그 · strength: 0..100(기본 1)
                rw/gw/bw: 밝기 가중치 · lightness: **boolean**(밝기 보존 여부)
```

- **`selectivecolor` 로는 채도를 못 올리고 색상을 못 돌린다.** CMYK 잉크를 더하고 빼는 것뿐이다.
  「빨간 옷의 채도만 +20%」·「초록 잎을 청록 쪽으로 8° 돌리기」는 표현 자체가 안 된다.
- **`huesaturation` 은 9계열이 아니라 6구간(r/y/g/c/b/m)뿐**이고 흰색·중간톤·검정을 못 건드린다.

→ **둘 다 필요하다.** S3 는 `hsl?: HslSecondary[]`(selectivecolor) 만 정의했으므로
**`hueSat?: HueSatBand[]` 를 추가한다** — optional 추가라 S3 를 깨지 않는다.

### 스키마

```ts
// packages/schema/src/index.ts — ClipSource 안
hsl?: HslSecondary[];        // S3 정의 그대로 (selectivecolor)
hueSat?: HueSatBand[];       // 추가 (huesaturation)

export type HslSecondary = {
  id: string;
  family: 'reds'|'yellows'|'greens'|'cyans'|'blues'|'magentas'|'whites'|'neutrals'|'blacks';
  cyan: number; magenta: number; yellow: number; black: number;   // -1..1
};

export type HueSatBand = {
  id: string;
  bands: ('r'|'y'|'g'|'c'|'b'|'m')[];   // 최소 1개
  hue: number;          // -180..180
  saturation: number;   // -1..1
  intensity: number;    // -1..1
  preserveLightness?: boolean;          // huesaturation 의 lightness (기본 false)
};
```

**엔진 검증:** `hsl` 안에서 `family` 가 **중복되면 `BAD_HSL`**. selectivecolor 는 계열마다 인자가
하나뿐이라 둘이 있으면 뒤엣것이 앞엣것을 조용히 덮어쓴다. `hueSat` 은 중복 허용(체인으로 쌓인다).

## 파이프라인 순서 — 판단이 필요했던 곳

S3 의 순서에 `hueSat` 을 **`hsl` 앞에** 끼워 넣는다:

```
1) stabilize   (vidstab 2패스)
2) matchTo     (colorlevels)
3) hueSat      (huesaturation)     ← 추가
4) hsl         (selectivecolor)
5) lut         (lut3d)
6) motionBlur
```

**근거:** 색보정 실무는 **primary(전체 노출·화이트밸런스·채도) → secondary(특정 색 다듬기)** 순이다.
`huesaturation` 은 6개 색 구간을 통째로 미는 광범위 조작(primary 쪽), `selectivecolor` 는 9계열의
CMYK 미세 조정(secondary 쪽)이다. 반대로 하면 미세 조정한 결과를 광범위 조작이 다시 밀어버린다.

**`correction_method` 는 `absolute`(기본)를 쓴다.** `relative` 는 이미 있는 잉크량에 비례해서
적용하므로 같은 값이라도 소스마다 결과가 다르다. W7 실측(빨강 109 변화)도 `absolute` 로 잰 것이다.
프리셋 값이 소스와 무관하게 같은 뜻을 가지려면 `absolute` 여야 한다.

### 굽는 자리

`packages/media/src/derive.ts` — `DeriveSpec` 에 `hsl`·`hueSat` 추가, 위 순서로 `-vf` 체인에 이어 붙인다.
```
huesaturation=colors=ry:hue=0:saturation=-0.15:intensity=0:strength=1,
selectivecolor=correction_method=absolute:reds=0.06 -0.05 0 0:yellows=0 0 -0.10 0
```
`matchTo`·`lut` 과 **같은 패스**다 — 패스가 늘지 않는다.
`sourceKey` 에 `hsl` 배열의 (family, c, m, y, k) 전부와 `hueSat` 배열의 (bands, hue, saturation,
intensity, preserveLightness) 전부를 **순서 그대로** 넣는다.

## UI — 9개 계열을 어떻게 고르게 할 것인가

드롭다운에 9개를 나열하는 건 실무에서 안 쓰는 방식이다. DaVinci·Premiere 는 **색상환에서 고르거나
화면에서 스포이드로 찍는다.** 셋 다 만든다.

### (1) 색 칩 — 색상환 배치 + 밝기 3단

```
        ● yellows
   ● reds      ● greens          [ whites   ]
   ● magentas  ● cyans           [ neutrals ]
        ● blues                  [ blacks   ]
```
6개 색 칩을 색상환 순서로, 밝기 3계열을 옆에 세로로. **각 칩을 그 계열의 실제 색으로 칠한다** —
글자로 「magentas」라고 쓰는 것보다 훨씬 빨리 찾는다. 이미 조정이 걸린 칩에는 점을 찍는다.

칩을 고르면 아래에 그 계열의 **CMYK 슬라이더 4개**가 열린다. 슬라이더 라벨은 색 이름이 아니라
방향으로 쓴다 — 「청록 ↔ 빨강」·「자홍 ↔ 초록」·「노랑 ↔ 파랑」·「밝게 ↔ 어둡게」.
(CMYK 를 모르는 사람도 슬라이더를 밀면 뭐가 되는지 안다.)

### (2) 스포이드 — 화면에서 찍으면 계열이 자동 선택

미리보기 캔버스에서 클릭 → 그 픽셀의 RGB → **어느 family 에 속하는지 계산해서 그 칩을 켠다.**
`GlCompositor` 에서 1픽셀 `readPixels` 로 얻는다(F6 스코프와 같은 경로).

**⚠️ 확인 필요 — family 판정 규칙.** selectivecolor 가 어떤 픽셀을 「reds」로 보는지는
ffmpeg `vf_selectivecolor.c` 의 내부 규칙(포토샵 방식: max/mid/min 채널 비교)이고, 나는 소스를
읽지 않았다. **추측으로 구현하면 스포이드가 엉뚱한 칩을 켠다.**
확인 방법: **9계열 각각을 극단값(`k=-1`)으로 하나씩 밀어 컬러바+그레이램프를 굽고, 어느 픽셀이
변했는지 RGB 로 기록해 판정표를 만든다.** 이건 아래 검증 2번과 같은 실험이라 한 번에 끝난다.
표가 나오기 전까지 스포이드는 **비활성**으로 둔다 — 틀린 칩을 켜느니 없는 게 낫다.

### (3) 프리셋 — 제일 위에

피부톤이 주 용도이므로 **피부톤 프리셋을 칩 위에 놓는다.** 클릭 한 번이면 값이 채워지고,
그다음 슬라이더로 다듬는다.

| 프리셋 | 인자 | 무엇을 고치나 |
|---|---|---|
| **피부 밝게** | `reds=0 0 0 -0.08` `yellows=0 0 0 -0.06` | K(검정 잉크)를 빼면 밝아진다 |
| **붉은기 빼기** | `reds=0.06 -0.05 0 0` | 시안↑ 자홍↓ — 얼굴이 벌건 것 |
| **노란기 빼기** | `yellows=0 0 -0.10 0` | 노랑↓ — 조명이 텅스텐일 때 |
| **혈색 살리기** | `reds=-0.04 0.03 0.02 0` | 창백한 얼굴 |
| **피부 채도 낮추기** | `huesaturation=colors=ry:saturation=-0.15` | AI 영상의 과채도 |
| **하늘 진하게** | `blues=0.10 0.04 0 0.05` | 배경 하늘만 |
| **초록 자연스럽게** | `greens=0 0 0.08 0` `huesaturation=colors=g:saturation=-0.10` | 형광 초록 잔디 |

**⚠️ 이 값들은 「전형적 출발점」이지 표준이 아니다.** W7 조사가 EQ 수치에 대해 적은 것과 같다.
피부색은 인종·조명·카메라마다 다르다. **UI 에 「출발점입니다 — 벡터스코프를 보고 다듬으세요」를
적는다.** 프리셋 파일은 `packages/schema/src/hsl-presets.ts` (신규, `templates.ts` 옆).

## 벡터스코프(F6) 연동 — 눈이 아니라 계기로 한다

피부톤이 맞았는지는 **벡터스코프의 스킨톤 라인**으로 판정한다. 인종과 무관하게 사람 피부는
벡터스코프에서 거의 같은 각도의 선 위에 놓인다 — 밝기만 다르다. 이게 색보정에서 스킨톤 라인이
표준 도구인 이유다.

### 흐름
1. 인물이 나오는 프레임에서 스코프 패널을 벡터스코프로 놓는다.
2. **피부 영역을 사각형으로 지정한다** (F4 의 region 과 같은 드래그 UI).
3. UI 가 그 영역의 평균 (Cb, Cr) → 각도를 계산해 **스킨톤 라인과의 차를 숫자로** 보여준다:
   > 피부톤이 스킨톤 라인에서 **+7° 벗어남 (노란기)** · 채도 반경 0.31
4. **「자동 보정」** 버튼 — 그 각도를 되돌리는 `hueSat` 을 만든다:
   `huesaturation=colors=ry:hue=-7:saturation=0:intensity=0`
   버튼은 값을 **채워 넣기만** 하고 바로 굽지 않는다. 사용자가 보고 확인한 뒤 적용한다.

계산: `Cb = -0.169R -0.331G +0.500B`, `Cr = 0.500R -0.419G -0.081B` (BT.601, F6 와 같은 식).
각도 = `atan2(Cr, Cb)`.

### 피부 픽셀을 어떻게 고르나 — 판단이 필요했던 곳

| | 사각형 지정 | 자동 피부 검출 |
|---|---|---|
| 정확도 | 사용자가 고른 것이 정답 | 나무·벽돌·흙·나무 바닥을 피부로 잡는 오검출이 흔하다 |
| 틀렸을 때 | 다시 그린다 | **왜 틀렸는지 알 수 없다** |
| 드는 시간 | 3초 | 0초 |

**사각형 지정만 만든다.** 자동 검출은 조용히 틀린 결과를 만드는데 사용자가 원인을 찾을 방법이 없다.
3초를 아끼려고 신뢰를 버리는 거래다. **이건 「어려우니 대신」이 아니다** — 자동 검출 구현은 오히려
쉽고(YCbCr 범위 규칙 20줄), 안 하는 이유는 결과를 믿을 수 없어서다.

### ⚠️ 확인 필요 — 스킨톤 라인의 각도

「약 33°」라는 값이 돌아다니지만 **좌표계(Cb/Cr 축 방향·부호)에 따라 달라진다.** ffmpeg
`vectorscope=graticule=green` 이 그리는 격자가 어느 각도에 선을 긋는지, 그리고 그것이 우리
브라우저 스코프의 좌표계와 같은지 **확인하지 않았다.**
확인 방법: **알려진 피부색 패치**(예: Macbeth 차트의 light skin `#F0D0C0` / dark skin `#735244`)를
단색 프레임으로 만들어 두 스코프에 넣고 각도를 잰다. 두 색이 같은 각도에 놓이면 그게 스킨톤 라인이다.
**F6 의 스코프 검증과 한 번에 한다.**

## 미리보기는 어떻게 되나

**파생을 굽는 방식이라 슬라이더가 즉시 반응하지 않는다.** 값을 바꾸면 잡이 돌고, 다 구워질 때까지
미리보기는 원본을 보여준다 — 지금 LUT·손떨림 보정과 똑같다. `SourceSection` 이 이미 「적용 중…
(미리보기는 원본)」 배지를 띄우고 있으므로 그대로 쓴다.

**즉시 반응하는 경로도 있다** — Remotion 코어의 `createEffect`(WebGL2/WebGPU/2D)로 합성 단계에서
거는 것. 하지만 S5 의 `chromiumOptions` 와 `<OffthreadVideo>` → `@remotion/media` 이사가 선행이고,
이 컴퓨터는 GPU 부하로 5번 다운된 적이 있다. **F15 뒤로 미룬다. 포기가 아니라 순서다.**

## 검증 — 숫자로 낸다

**1. W7 실측 재현** — `selectivecolor=reds=0.35 0 -0.25 0` 을 컬러바에 걸어 **빨강만 109 변화,
나머지 5색 변화량 정확히 0**. 재현이 안 되면 `correction_method` 나 인자 형식이 다른 것이다.

**2. 9계열 판정표 만들기** (위 「확인 필요」 2건을 한 번에 해결) — 9계열 각각을 `k=-1` 로 밀어
**컬러바 + 0~100% 그레이 램프**를 굽고, 어느 색·어느 밝기 구간이 변했는지 RGB 로 기록한다.
- whites/neutrals/blacks 는 컬러바에 안 나오므로 **그레이 램프로만** 잰다.
- 결과가 판정표가 되고, 그 표로 스포이드를 구현한다.
- **각 계열이 서로 겹치는 구간이 있는지도 기록한다** — 겹치면 두 계열을 동시에 만졌을 때
  결과가 합쳐진다는 뜻이고, UI 에 알려야 한다.

**3. 프리셋 5종 + 하늘·초록** — 실제 인물 프레임(또는 Macbeth 피부 패치)에 걸어
**벡터스코프 각도가 스킨톤 라인에 얼마나 가까워지는지 각도로** 잰다.
「붉은기 빼기」·「노란기 빼기」가 **각도 차를 줄여야** 합격. 늘리면 값이 틀린 것이다.

**4. `huesaturation` 의 구간 분리** — `colors=r` 만 켜고 saturation=+0.5 를 걸었을 때
**빨강 채도만 오르고 나머지 5구간은 변화 0** 인지. (selectivecolor 와 같은 검사)

**5. 순서 근거** — 같은 클립에 `hueSat`+`hsl` 을 걸고 순서를 바꿔 구운 두 파일의 픽셀 차이를 잰다.
**다르다는 것을 확인**해야 「hueSat 이 먼저」가 근거 있는 고정이 된다.

**6. 중복 family 거부** — 같은 family 두 개를 넣으면 `BAD_HSL` 로 거부되는지.

**7. `sourceKey` 빠뜨림 검사** — `hsl`·`hueSat` 의 **모든 필드와 배열 순서**에 대해 다른 키가 나오는지.
배열 순서가 바뀌면 결과가 달라지므로(체인 순서) 키도 달라야 한다.

**8. 시간** — 1080×1920 30초 클립에 `hsl`+`hueSat` 을 걸었을 때의 파생 굽기 시간을 `lut` 만 걸었을
때와 비교. **같은 패스라 늘지 않아야** 한다(±10%).

## 하지 않을 것

- **자동 피부 검출로 도망가지 않는다.** 사각형 지정이 3초다.
- **9계열 중 「자주 쓰는 것만」 넣지 않는다.** whites/neutrals/blacks 도 다 넣는다 — 검정만
  살짝 들어 올리는 건 광고에서 흔한 룩이다.
- **`selectivecolor` 하나로 퉁치지 않는다.** 채도·색상 회전이 안 되면 피부톤 보정의 절반이 빠진다.
- **판정 규칙을 추측으로 구현하지 않는다.** 판정표가 나오기 전까지 스포이드는 비활성.
- **「미리보기가 즉시 안 되니 안 만든다」로 가지 않는다.** 굽는 동안 원본이 보인다고 표시하고,
  즉시 반응 경로는 F15 뒤로 순서를 미룬다.
