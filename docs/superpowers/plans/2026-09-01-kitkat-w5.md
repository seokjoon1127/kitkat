# kitkat W5 구현 계획 — 확장 백로그 18종 (2026-09-01)

> **For agentic workers:** v1 계획(`2026-09-01-kitkat-v1.md`)과 같은 방식으로 웨이브(XW-1~XW-4) 단위 실행.
> 각 에이전트는 [Global Constraints + Contracts X1~X9 + 자기 태스크 섹션]을 프롬프트로 받는다.
> 태스크끼리 **파일 소유권이 겹치지 않는다.** 빌드 의존이 있으면 같은 웨이브 안에서 체인(순차).

**Goal:** v1에서 W5로 미룬 18개 기능을 전부 구현한다 — 전환·효과 확장, LUT, 커브 속도, 스티커/GIF,
텍스트 템플릿, 비트 감지, 더킹, 피치 보정, 커버 지정, 정지화면, 손떨림 보정, 색조정 커브,
MOV/알파 내보내기, 보컬 분리, 잡음 제거, 업스케일, 프레임 보간, 프리뷰 엔진 v2.

**Spec:** `PRD.md` §5 ①②③군의 W5 이관분.

## 설계 요약 — 18개를 7개 메커니즘으로 묶는다

기능 18개를 따로따로 만들면 문서·엔진·렌더러가 누더기가 된다. 아래 7개 축으로 묶어 개념 수를 줄인다.

| 메커니즘 | 무엇인가 | 담는 기능 |
|---|---|---|
| **M1 합성 확장** | 스키마 상수 + 렌더러 CSS/SVG. 파일 생성 없음 | 전환 확장(12종↑), 효과 확장(11종↑), 색조정 커브, 텍스트 템플릿, 정지화면, 스티커/GIF |
| **M2 파생 미디어** | 클립에 `source` 를 달면 서버가 ffmpeg 로 그 클립 전용 파일을 굽고, 렌더·미리보기가 그 파일을 쓴다 | LUT, 손떨림 보정, 잡음 제거, 피치 보정 |
| **M3 신규 에셋** | 원본에서 **다른 에셋**을 만들어 낸다 | 보컬 분리, 업스케일, 프레임 보간 |
| **M4 분석→데이터** | 오디오를 분석해 문서에 숫자를 남기고, 그 숫자로 편집한다 | 비트 감지, 더킹 |
| **M5 출력 확장** | 렌더 경로의 코덱·정지컷 | MOV/알파 내보내기, 커버 지정 |
| **M6 커브 속도** | 한 클립 안에서 속도가 변한다 | 커브 속도 |
| **M7 프리뷰 v2** | WebCodecs 디코딩 + WebGL 합성 미리보기 | 프리뷰 엔진 v2 |

### 결정과 근거 (사용자 승인 없이 자율 진행한 판단 — 되돌릴 수 있음)

- **D8 LUT 는 ffmpeg 로 굽는다(M2), 브라우저에서 근사하지 않는다.** 3D LUT 는 CSS/SVG 필터로
  표현이 불가능하다(SVG 는 채널별 1D 곡선까지만). 크로마키처럼 "근사"로 가면 미리보기와 결과물의
  색이 달라진다 — P3(결과물 무타협)에 어긋난다. 대신 `lut3d` 로 구운 파일을 미리보기·렌더가
  **똑같이** 쓴다. 대가: 필터를 바꿀 때마다 굽는 시간(540p 프록시 기준 몇 초). 굽는 동안에는
  원본을 그대로 보여주고 완료되면 자동 교체한다.
- **D9 손떨림·잡음·피치도 같은 M2 메커니즘에 태운다.** 넷 다 "원본을 전처리한 파일이 필요하다"는
  같은 문제다. `reversedSrc`(v1)와 같은 패턴을 일반화한 것이라 새 개념이 하나만 는다.
- **D10 업스케일·프레임 보간은 ffmpeg 으로 한다(Real-ESRGAN·RIFE 대신).** PRD 는 ML 모델을
  적었지만 둘 다 torch(2.5GB+) 설치가 필요하고 이 머신에 없다. ffmpeg `minterpolate`(움직임 보상
  프레임 보간)는 품질이 충분하고, 업스케일은 `lanczos+unsharp` 로 간다. **보컬 분리만 ffmpeg 에
  대체재가 없어서 Python/Demucs 로 간다** — 설치는 최초 1회 지연 설치, 실패 시 501 로 명확히 알린다.
- **D11 프리뷰 v2 는 기본 꺼짐, 토글로 켠다.** Remotion Player 가 WYSIWYG 기준선이다. v2 는
  반응성을 위한 것이므로 기준선을 대체하지 않는다. 발산을 막기 위해 **레이아웃 수식을
  `@kitkat/renderer/layout` 순수 모듈로 뽑아 Remotion 합성과 WebGL 합성이 같은 코드를 쓴다.**
- **D12 스키마 버전은 1 그대로.** W5 추가 필드가 전부 optional 이라 v1 문서가 그대로 유효하다.
  마이그레이션 코드를 만들지 않는다.

### 사전 검증 완료 (이 머신에서 실제 실행 확인)

`lut3d` · `lut3d+blend(강도 혼합)` · `rubberband`(피치) · `afftdn`(잡음) · `minterpolate`(보간) ·
`vidstabdetect/transform`(손떨림) · `libvpx-vp9 yuva420p`(알파 webm) · `prores_ks 4444 yuva444p10le`(알파 MOV) ·
`@remotion/renderer` 의 `renderStill` — 전부 통과.

## Global Constraints (v1 과 동일 + 추가)

- **전부 로컬.** 외부 유료 API 금지. fal.ai 금지. Anthropic API 금지. 예외 없음.
- **시간은 정수 ms.** 프레임 변환은 렌더러에서만.
- **ESM 전용.** ui 패키지만 `moduleResolution: "Bundler"`, 나머지는 `NodeNext` — **상대 import 에 반드시 `.js` 확장자.**
- **문서에 저장되는 경로는 forward slash 전용.**
- **최종 렌더는 Remotion 내장 인코더** (h264 / prores). `detectEncoder()` 는 ffmpeg 직접 인코딩 경로에만.
- **파일 소유권:** 자기 태스크 Files 목록 + 자기 패키지 `test/`. 루트 설정 파일 수정 금지. **npm install 금지.**
- UI 문자열은 한국어.
- **W5 추가 필드는 전부 optional.** 기존 문서·기존 테스트를 깨지 않는다. 기존 테스트가 깨지면 그건 버그다.
- **기존 동작을 바꾸지 않는다.** 새 필드가 없는 클립은 v1 과 픽셀 단위로 같게 렌더돼야 한다.

## 실행 그래프

- **XW-1 (코어):** 체인① schema → engine · 체인② media · 체인③ ai — 동시 3체인, 4에이전트
- **XW-2 (렌더·서버):** 체인① renderer → server · 체인② mcp — 동시 2체인, 3에이전트

## 공유 계약 (Contracts X1~X9)

### X1. 스키마 확장 (`@kitkat/schema`)

`SCHEMA_VERSION` 은 **1 그대로**. 아래는 전부 추가(기존 필드 변경 없음).

```ts
// ── 전환 20종 (v1 8종 + W5 12종) ──
export const TRANSITION_TYPES = [
  'fade','slideLeft','slideRight','slideUp','slideDown','wipeLeft','zoomIn','zoomOut',
  'wipeRight','wipeUp','wipeDown','circleOpen','circleClose','blurFade',
  'whiteFlash','blackFlash','spin','bounce','shake','glitch',
] as const;

// ── 효과 20종 (v1 9종 + W5 11종) ──
export const EFFECT_TYPES = [
  'brightness','contrast','saturation','hue','blur','vignette','grayscale','sepia','invert',
  'temperature','tint','exposure','highlights','shadows','sharpen',
  'glow','grain','scanlines','chromaShift','lightLeak',
] as const;
// W5 params 기본값:
//  temperature {amount:0}   -1(차갑게)..1(따뜻하게)
//  tint        {amount:0}   -1(초록)..1(자홍)
//  exposure    {stops:0}    -2..2 (EV)
//  highlights  {amount:0}   -1(밝은 곳 누르기)..1(올리기)
//  shadows     {amount:0}   -1(어두운 곳 누르기)..1(올리기)
//  sharpen     {amount:0}   0..2
//  glow        {amount:0.5, radius:16}   amount 0..1, radius 0..40 px
//  grain       {amount:0.3}              0..1
//  scanlines   {amount:0.3, lines:600}   amount 0..1, lines 100..2000
//  chromaShift {px:4}                    0..20
//  lightLeak   {amount:0.4, hue:30}      amount 0..1, hue 0..360

// ── 색조정 커브 ──
export type CurvePoint = { x: number; y: number };   // 0..1. x 오름차순, 최소 2점(0과 1 포함 권장)
export type ColorCurves = { rgb?: CurvePoint[]; r?: CurvePoint[]; g?: CurvePoint[]; b?: CurvePoint[] };

// ── 파생 미디어 스펙 (M2) ──
export type ClipSource = {

  stabilize?: { smoothing: number };             // 1..100 (vidstabtransform smoothing 프레임 수)
  denoise?: { amount: number };                  // 0..1 → afftdn nr = amount*40 (dB)

// ── 속도 커브 (M6) ──
export type SpeedPoint = { u: number; speed: number };  // u = 소스 구간 진행도 0..1, speed 0.1..100
export type SpeedRamp = { points: SpeedPoint[] };       // u 오름차순, points[0].u===0, 마지막 u===1, 최소 2점

// ── 텍스트 템플릿 (M1) ──
export type TextTemplate = {
  id: string; name: string; style: TextStyle;
  animationIn?: { type: TextAnimType; duration: number };
  animationOut?: { type: TextAnimType; duration: number };
  transform?: Transform;
  highlightColor?: string;
};
export const TEXT_TEMPLATES: readonly TextTemplate[];   // 10종 (아래 X1-b)

export const SPEED_RAMP_PRESETS: readonly { id: string; name: string; points: SpeedPoint[] }[];  // 6종 (X1-c)

// ── Asset 확장 ──
export type DerivedMedia = { src: string; proxySrc?: string };
// Asset.kind 에 'lut' 추가 → 'video' | 'audio' | 'image' | 'lut'
// Asset.derived?: Record<string, DerivedMedia>   // sourceKey → 파생 파일
// Asset.beats?: number[]                          // ms 오름차순 (비트 감지 결과)

// ── ClipBase 확장 ──
// curves?: ColorCurves

// ── VideoClip 확장 ──
// source?: ClipSource
// speedRamp?: SpeedRamp
// freeze?: boolean    true면 in 프레임을 duration 내내 정지. duration 은 (out-in)/speed 와 무관
// loop?: boolean      true면 소스를 반복해 duration 을 채움. duration 은 (out-in)/speed 와 무관

// ── AudioClip 확장 ──
// source?: { denoise?: {amount:number}; pitch?: {semitones:number} }

// ── settings 확장 ──
// settings.coverMs?: number    // 커버(대표 이미지) 프레임 시각 ms
```

**duration 불변식 예외:** VideoClip 이 `freeze===true` 또는 `loop===true` 면
`duration === (out-in)/speed` 검사를 **하지 않는다**. `speedRamp` 가 있으면 그 검사 대신
`|duration - rampDurationMs(clip)| <= 2` 를 검사한다. (schema Zod · engine `doAddClip` ·
`checkInvariants` 세 곳 모두 같은 규칙.)

**freeze 클립 규약:** `out === in + 1`, `speed === 1`, `freeze: true`. 소스 구간 1ms 는
"in 시점의 한 프레임"이라는 뜻이고 실제 표시 길이는 `duration`.

#### X1-b. `derive.ts` — 순수 파생 헬퍼 (schema 가 export, renderer·server·ui 공용)

zod·remotion 무의존 순수 함수. **여기 두는 이유:** renderer 와 server 가 똑같은 계산을 해야 하는데
renderer 에 engine 의존을 새로 만들지 않기 위해서다.

```ts
/** ClipSource + reversed → 안정 키 "s" + FNV-1a 32bit hex(8자). source 없으면 null. */
export function sourceKey(clip: VideoClip | AudioClip): string | null;

/** 속도 램프를 적분한 타임라인 길이(ms). speedRamp 없으면 (out-in)/speed. */
export function rampDurationMs(clip: VideoClip): number;

/** 램프를 등속 세그먼트로 전개. 렌더러가 세그먼트마다 OffthreadVideo 를 하나씩 놓는다. */
export function rampSegments(
  clip: VideoClip,
  maxSegments?: number,   // 기본 40
): { startMs: number; durationMs: number; inMs: number; outMs: number; speed: number }[];

/** ColorCurves 를 채널별 33개 테이블로 샘플링 (SVG feFuncR/G/B tableValues 용). */
export function curvesToTables(c: ColorCurves): { r: number[]; g: number[]; b: number[] } | null;
```

- `sourceKey`: `JSON.stringify` 를 쓰지 말고 **키 순서를 고정한 정규화 문자열**을 만든 뒤 FNV-1a.
  숫자는 소수점 4자리로 반올림해서 문자열화(부동소수 잡음으로 키가 갈리는 것 방지).
  `clip.reversed === true` 면 정규화 문자열에 `|rev` 를 붙인다.
- `rampSegments`: 소스 구간 `[in,out]` 을 균등 분할(최대 maxSegments)하고, 각 구간의 평균 속도로
  등속 세그먼트를 만든다. 세그먼트 durationMs 합 === `rampDurationMs`(반올림 오차는 마지막
  세그먼트가 흡수). 세그먼트 경계는 정수 ms.
- `curvesToTables`: rgb(마스터) 를 먼저 적용하고 그 위에 채널별 커브를 합성 —
  `table[i] = curveR(curveRgb(i/32))`. 커브 보간은 **단조 3차 (monotone cubic / Fritsch-Carlson)**
  로 해서 오버슈트가 안 나게 한다. 커브가 하나도 없으면 null.

### X2. 엔진 확장 (`@kitkat/engine`) — 명령 4종 추가 (총 23종)

```ts
| { type: 'freezeFrame'; clipId: string; at: number; duration: number;
    newClipIds?: [string, string] }        // [정지클립 id, 오른쪽 조각 id]
| { type: 'setSpeedRamp'; clipId: string; points: SpeedPoint[] | null }   // null = 램프 해제
| { type: 'duckTrack'; musicTrackId: string; voiceTrackId: string;
    amount: number; attackMs: number; releaseMs: number }
| { type: 'applyTextTemplate'; clipId: string; templateId: string }
```

- **`freezeFrame`** — video 클립 전용. `at` 에서 클립을 나누고 그 사이에 정지 클립을 끼운다.
  결과 3조각: 왼쪽(원본 앞) / 정지(`freeze:true`, `in = 소스시각(at)`, `out = in+1`, `speed:1`,
  `duration`) / 오른쪽(원본 뒤, `start = at + duration`). **같은 트랙의 뒤쪽 클립들도 `duration`
  만큼 뒤로 민다** (다른 트랙은 건드리지 않는다 — 겹침이 나면 EngineError).
  `newClipIds` 미지정 시 서버가 채운다(`splitClip` 과 같은 결정성 규칙, C3).
  reversed 클립은 splitClip 과 같은 미러링 규칙을 따른다.
- **`setSpeedRamp`** — video 클립 전용. points 검증(u 오름차순·0 시작·1 끝·speed 0.1..100·최소 2점)
  후 `clip.speedRamp = {points}`, `clip.duration = rampDurationMs(clip)`.
  `points: null` 이면 `speedRamp` 삭제 + `duration = round((out-in)/speed)` 복원.
  결과가 겹치면 EngineError(`OVERLAP`).
- **`duckTrack`** — music 트랙의 각 오디오 클립에 volume 키프레임을 생성한다.
  voice 트랙 클립들이 차지한 구간(합집합)에서 볼륨을 `amount`(0..1, 0.2 = 원래의 20%)까지 낮추고,
  구간 진입 `attackMs` 전부터 내려가고 구간 종료 후 `releaseMs` 동안 올린다.
  각 music 클립 기준 상대 ms 로 변환해 `clip.keyframes` 의 volume 키프레임만 교체(다른 prop 은 보존).
  겹치는 구간이 없으면 그 클립의 volume 키프레임을 지운다.
  `amount` 0..1, `attackMs`/`releaseMs` 0..5000 밖이면 EngineError.
- **`applyTextTemplate`** — text 클립 전용. `TEXT_TEMPLATES` 에서 찾아 `style`·`animationIn`·
  `animationOut`·`transform`·`highlightColor` 를 덮어쓴다(템플릿에 없는 필드는 **삭제**).
  `text`·`words` 는 건드리지 않는다. 없는 templateId 는 EngineError(`TEMPLATE_NOT_FOUND`).

추가 export (테스트 대상):
```ts
export function duckKeyframes(
  musicClip: AudioClip, voiceIntervals: {start:number; end:number}[],
  amount: number, attackMs: number, releaseMs: number,
): Keyframe[];
```

`FORBIDDEN_PATCH_KEYS` 에 **`freeze`·`loop`·`speedRamp` 를 추가**한다 — 이 셋은 duration 과
연동되므로 전용 명령(`freezeFrame`/`setSpeedRamp`) 또는 `addClip` 으로만 설정한다.
`loop` 는 `updateClip` 금지 대신 **`setClipLoop` 를 만들지 않는다** — 스티커는 `addClip` 시점에
`loop:true` 로 넣고, 길이는 `trimClip`(text/image 규칙과 같이 duration 만 조정)으로 늘인다.
따라서 `doTrimClip` 은 `freeze`/`loop` 클립을 **text/image 와 같은 분기**(start/duration 만 조정)로 처리한다.

`splitClip`·`trimClip` 은 `speedRamp` 가 걸린 video 클립을 거부한다(`BAD_RAMP`). 소스 분할점을
`leftDur*speed` 로 계산하는 전제가 램프에서는 성립하지 않기 때문이다. 사용자는 먼저
`setSpeedRamp(points:null)` 로 램프를 풀어야 한다.

`source`·`curves` 는 `updateClip` 으로 자유롭게 patch 한다(파일 생성은 서버가 감시).

**ffmpeg 명령 (이 머신에서 검증된 형태 — 그대로 쓸 것):**

- 손떨림 2패스 (있으면 **항상 먼저**, 별도 패스):
  ```
  ffmpeg -y -i SRC -vf vidstabdetect=shakiness=5:result=<tmp>/tr.trf -f null -
  ffmpeg -y -i SRC -vf vidstabtransform=input=<tmp>/tr.trf:smoothing=<S>,unsharp=5:5:0.8:3:3:0.4 <enc> OUT
  ```
- LUT (강도 혼합):
  ```
  -filter_complex "[0:v]split[a][b];[b]lut3d=file=<CUBE>[l];[a][l]blend=all_mode=normal:all_opacity=<I>[v]"
  -map "[v]" -map 0:a? 
  ```
  intensity >= 0.999 면 `-vf lut3d=file=<CUBE>` 로 단순화한다.
- 오디오 체인 (한 패스에 합침): `-af "afftdn=nr=<amount*40>:nf=-25,rubberband=pitch=<2^(semitones/12)>"`
  — 둘 중 있는 것만 이어 붙인다.
- 업스케일: `-vf "scale=iw*<S>:ih*<S>:flags=lanczos,unsharp=5:5:0.6:5:5:0.0"`
- 프레임 보간: `-vf "minterpolate=fps=<F>:mi_mode=mci:mc_mode=aobmc:vsbmc=1"`
- 스티커: `-vf format=rgba -c:v libvpx-vp9 -pix_fmt yuva420p -auto-alt-ref 0`
- 인코딩 인자는 기존 `videoEncoderArgs(detectEncoder(), 18)` 사용. 프록시는 `scale=-2:540` + crf 28.
- 진행률은 `-progress pipe:1` 의 `out_time_us` / 전체 길이로 계산한다.

**LUT 없는 spec 은 그 필터를 건너뛴다.** spec 이 전부 비면 throw(`빈 파생 스펙`).

`detectBeats` 구현: `-ac 1 -ar 22050 -f s16le` PCM → 1024 샘플 홉의 크기 스펙트럼 차분 합
(스펙트럼 플럭스) → 이동 평균 임계(윈도우 ±20홉, 계수 1.5) 초과 지역 최대점 → 최소 간격 200ms.
**순수 함수 `beatsFromPcm(pcm: Int16Array, sampleRate: number): number[]` 를 따로 export** 해서
합성 클릭 트랙으로 단위 테스트한다(FFT 는 직접 구현하거나 라디스-2 재귀 DFT 로 충분).

#### X5-b. 합성 구현

- **전환 20종** — `transitions.tsx` 에 12종 추가.
  `circleOpen/Close`: `clipPath: circle(N% at 50% 50%)` · `blurFade`: opacity + `filter: blur()` ·
  `whiteFlash/blackFlash`: 전체 덮개 div 의 opacity(전환 중앙에서 1) · `spin`: rotate+scale+opacity ·
  `bounce`: easeOutBack 의 translateY · `shake`: `sin(진행도*6π)` 의 translateX ·
  `glitch`: translateX 지터 + hue-rotate + 가로 슬라이스 clip-path 2겹.
  덮개가 필요한 전환(whiteFlash/blackFlash/glitch)은 `activeTransitionStyles` 가 스타일만 주는
  구조로는 부족하므로 **`activeTransitionOverlays(...)` 를 추가**해 오버레이 노드를 따로 돌려준다.
- **효과 20종** — CSS filter 로 되는 것은 `effects.ts` 에서 처리, 나머지는 SVG/오버레이:
  - `temperature`/`tint`/`exposure` → `feColorMatrix` (선형 RGB 가중), `exposure` 는 `brightness(2^stops)` 로 근사 가능하면 CSS 로.
  - `highlights`/`shadows` → `feComponentTransfer` 테이블 (하이라이트·섀도 영역만 밀어 올리는 곡선).
  - `sharpen` → `feConvolveMatrix` 3x3 언샤프.
  - `glow` → `feGaussianBlur` + `feComposite` screen 합성.
  - `grain` → `feTurbulence` 오버레이(`mixBlendMode: overlay`, 프레임마다 seed 변경).
  - `scanlines` → `repeating-linear-gradient` 오버레이.
  - `chromaShift` → R/B 채널만 `feOffset` 으로 좌우로 민 뒤 합성.
  - `lightLeak` → 대각 `linear-gradient` 오버레이 + `mixBlendMode: screen`.
- **색조정 커브** — `curvesToTables(clip.curves)` → `feComponentTransfer` 의 `feFuncR/G/B type="table"`.
  적용 순서는 **커브 → 효과** (색보정이 먼저, 스타일 효과가 나중)인데, 효과 중 일부는 CSS `filter`
  로 나가고 CSS `filter` 리스트는 **왼쪽부터** 적용된다. 그래서 커브를 효과와 같은 `<filter>` 에
  넣으면 CSS 효과가 커브보다 먼저 걸려버린다(예: 커브+`invert` → 원본이 아니라 **반전된 영상**의
  그림자가 올라간다). 따라서 커브는 **자기만의 `<filter id="curves-<클립id>">`** 로 떼어
  CSS 효과 **앞**에 붙인다 — 최종 문자열은
  `url(#curves-<id>) <CSS 효과들> url(#fx-<id>)` (`url()` 은 CSS filter 리스트 안에 섞을 수 있다).
  커브가 없으면 `url(#curves-…)` 를 아예 넣지 않는다(커브 없는 클립의 문자열 = v1 그대로).
  효과 SVG 스테이지와 크로마키는 종전대로 `fx-<클립id>` **하나의 `<filter>`** 안에서 배열 순서대로
  이어 붙고, 크로마키는 그 체인의 맨 끝이다.
  (`layout.curvesFilters`/`layout.effectFilters` 가 두 필터의 스테이지, `layout.svgFilters` 는
  둘을 이어 붙인 전체 색 연산 순서다. 프리뷰 v2 도 **커브 → CSS 연산 → 효과 체인** 순으로 맞춘다.)
- **freeze** — `<Freeze frame={msToFrames(inMs, fps)}>` 로 `OffthreadVideo` 를 감싼다.
- **loop** — `<Loop durationInFrames={소스길이프레임}>` 로 감싼다. 소스 길이 = `(out-in)/speed`.
- **speedRamp** — `rampSegments(clip)` 를 돌며 세그먼트마다
  `<Sequence from={msToFrames(seg.startMs)} durationInFrames={...}>` + `OffthreadVideo`
  (`trimBefore/After` = seg.inMs/outMs, `playbackRate` = seg.speed). **램프가 있으면 오디오는 음소거**
  (세그먼트 경계 클릭음 방지). 램프 없으면 v1 경로 그대로.
  세그먼트가 채우는 프레임 수의 기준은 `rampDurationMs` 가 아니라 **`clip.duration`** 이다 —
  스키마가 `|duration - rampDurationMs| <= 2ms` 를 허용해서 둘이 한 프레임 갈릴 수 있고,
  그러면 클립 마지막 프레임에 `OffthreadVideo` 가 하나도 없어 **검은 프레임**(투명 내보내기면
  구멍)이 낀다. 마지막 세그먼트를 `msToFrames(clip.duration)` 까지 늘려 끝을 맞춘다.
- **파생 미디어 선택** — `media-src.ts` 의 `resolveMediaSrc` 를 확장:
  `const k = sourceKey(clip); const d = k ? asset.derived?.[k] : undefined;`
  `d` 가 있으면 `proxy ? (d.proxySrc ?? d.src) : d.src` 를 쓴다(**reversed 보다 우선** — 파생 파일은
  이미 역재생본에서 구워졌다). 없으면 v1 규칙(reversed → proxy → src).
  **단, `clip.reversed === true` 인 파생은 소스 구간을 계속 미러링한다** — 그 파생은 `reversedSrc`
  에서 구워졌고 길이가 원본과 같으므로, 미러링을 빼면 엉뚱한 구간이 재생된다
  (`resolveMediaWindow` 의 미러링 조건 = `useReversed || (useDerived && clip.reversed)`).
- **`lut` kind 에셋은 절대 렌더 대상이 아니다** — `TimelineVideo` 는 그런 클립을 만들 수 없다
  (트랙 kind 검사로 이미 막힘). 방어적으로 무시만 하면 된다.

- **에셋 임포트 확장** (`routes/assets.ts`):
  - 확장자 `.cube`/`.3dl` → `parseCubeLut` 검증 후 `kind:'lut'` 에셋으로 등록, **후처리 잡 없음**.

(Remotion 이 배속을 트림 길이에 반영하지 않음) · **h264_qsv 가 vidstab 출력에서 액세스 위반으로
프로세스째 죽는 문제**(libx264 자동 폴백).

미조치(PLAUSIBLE 1건): MCP·HTTP 로 `restoreDoc` 을 직접 보내면 `derived` 가 사라질 수 있음.
브라우저 UI 의 undo 경로에는 이미 보호가 있고 실제 재현되지 않았다.

## 회귀 방지 (모든 태스크 공통)

W5 의 가장 큰 위험은 **v1 기능을 깨는 것**이다. 각 태스크는 자기 패키지의 기존 테스트를
하나도 빠짐없이 통과시킨 상태로 끝낸다. 기존 테스트를 고쳐야 한다면 그건 계약을 바꾼 것이므로
**고치기 전에 이 문서의 계약을 먼저 고쳐야 한다.**
