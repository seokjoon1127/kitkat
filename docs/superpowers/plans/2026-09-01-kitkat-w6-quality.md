## 결정

- **D13 크로마키는 합성 단계에서 고친다(굽지 않는다).** ffmpeg `chromakey`+`despill` 로 구우면
  정확하지만, 키를 맞추려면 similarity 를 계속 조정해야 하는데 그때마다 클립 전체를 다시 굽는다.
  **합성에서 고치면 미리보기가 즉시 반응하고 렌더와 정확히 같다.** M2 파생은 「한 번 정하면 끝」인
  LUT·손떨림에 맞고, 크로마키는 아니다.
- **D14 크로마키 판정은 「휘도를 뺀 색차 공간에서의 투영」으로 바꾼다.** 지금은 RGB 벡터를 키 색
  방향에 투영해서 **밝을수록 지워진다**. 휘도를 먼저 빼면 밝기와 무관해진다. 실계산 결과(키 #00b140):

  | 색 | 지금 방식(dot) | 새 방식(색차 투영) |
  |---|---|---|
  | 키 그린 | 0.738 | **0.539** |
  | 밝은 피부 | 0.851 ← 지워짐 | -0.082 |
  | 흰옷 | 1.280 ← 지워짐 | 0.000 |
  | 하늘색 옷 | 1.073 ← 지워짐 | 0.139 |
  | 어두운 피부 | 0.361 | -0.082 |

  새 방식은 키 그린 0.539 vs 그 다음(하늘색) 0.139 로 **약 4배 여유**가 난다. 그리고 이 값은
  **R·G·B 의 선형 결합**이라 `feColorMatrix` 한 줄로 표현된다.
- **D15 폰트는 media/fonts/ 에 넣고 mediaBase 로 참조한다.** 렌더러 정적 서버와 UI 가 이미
  `mediaBase` 로 media/ 를 서빙하므로 `@font-face { src: url('${mediaBase}/fonts/…') }` 하나로
  미리보기·렌더 양쪽이 같은 폰트를 쓴다. 시스템 설치에 의존하지 않는다.
- **D16 Real-ESRGAN 은 «있으면 쓰고 없으면 lanczos» 백엔드로 붙인다.** 실행 파일이 없어도
  업스케일 기능은 지금처럼 동작해야 한다.

## T1. 크로마키 재작성 (G1)

### 스키마
```ts
export type ChromaKey = {
  color: string; similarity: number; smoothness: number;
  spill?: number;   // 0..1 — 경계에 남는 키 색 물듦 제거 강도. 기본 0.5 (신규, optional)
};
```
기존 3필드 의미는 유지(v1 문서 그대로 유효). `spill` 만 추가.

### 판정식 (렌더러·프리뷰 공통)
```
luma(c)   = 0.299R + 0.587G + 0.114B
chroma(c) = c - luma(c)·(1,1,1)
ĉ_key     = normalize(chroma(keyColor))
m(pixel)  = chroma(pixel) · ĉ_key            // 선형 → feColorMatrix 한 줄
mKey      = |chroma(keyColor)|               // 키 색 자신의 점수
```
- `similarity` 0..1 → 임계 `t = mKey · (1 - similarity·0.9)` … **similarity 가 클수록 더 많이 지운다**
  (지금과 방향 동일). 계수 0.9 는 similarity=1 에서도 임계가 0 이 되지 않게 하는 하한.
- `smoothness` 0..1 → 임계 주변 폭 `w = max(0.01, smoothness · mKey · 0.5)`.
- `alpha' = origA · clamp01((t + w/2 - m) / w)` — m 이 t-w/2 이하면 완전 불투명, t+w/2 이상이면 완전 투명.

### 디스필
키 색 성분이 남은 픽셀에서 그 성분을 뺀다:
```
spillAmt = max(0, m - t) · spill        // 임계를 넘은 만큼만
rgb' = rgb - spillAmt · ĉ_key           // 색차 방향으로만 빼서 휘도는 보존
```

### SVG 필터 구성 (`packages/renderer/src/composition/`)
1. `feColorMatrix type="matrix"` — m 을 알파가 아닌 **여분 채널**에 담고, 동시에 원본 RGB 보존.
   (m 은 음수가 될 수 있으므로 `0.5 + m·k` 형태로 오프셋해서 담는다.)
2. `feComponentTransfer` `type="table"` — 위 램프(불투명↔투명)를 테이블로. 램프는 구간별 선형이라
   테이블로 정확히 표현된다.
3. 디스필: 같은 방식으로 spillAmt 를 만들어 `feComposite operator="arithmetic"` 으로 RGB 에서 뺀다.
4. 결과를 원본 알파와 곱한다.

**중간 채널 사용 규칙:** 각 단계의 입력·출력을 `result=` 로 명시하고, 마지막에 원본 RGB + 새 알파를
합친다. 채널 패킹이 헷갈리기 쉬우니 **각 primitive 의 의미를 주석으로 적어라.**

### 프리뷰 v2
WebGL 에서는 위 수식을 **셰이더로 그대로** 구현한다(3~4줄). 지금 「크로마키는 못 그림」 배지를
**제거**한다 — 이제 정확히 그린다.

### 검증 (필수)
- 합성 그린스크린(#00b140 배경 + 살구색 피사체 + 가는 선 2개)을 **실제로 렌더**해서 알파 MOV 로 뽑고,
  픽셀을 읽어 확인:
  - 배경 알파 = 0
  - 피사체 한가운데 알파 = 255, 색이 원본 살구색(#e8b48c)과 채널당 ±8 이내
  - 가는 선(3px)이 살아있는지
  - 피사체 경계에서 **초록 물듦이 없는지** (경계 픽셀의 G 가 (R+B)/2 보다 크게 높지 않은지)
- 밝은 피부·흰옷·하늘색 옷 색을 넣었을 때 **지워지지 않는지** 단위 테스트

## T2. 폰트 번들 (G2)

`media/fonts/` 에 자유 라이선스(OFL) 한글 폰트를 넣고 렌더러·UI 가 로드한다.

**받을 곳:** `https://github.com/google/fonts/raw/main/ofl/<slug>/<File>.ttf` (구글 폰트 공식 저장소).
**OFL 라이선스 파일(OFL.txt)도 같이 받아 `media/fonts/licenses/` 에 둔다** — OFL 은 라이선스 동봉을 요구한다.

| 이름 | slug | 용도 |
|---|---|---|
| Noto Sans KR (Regular/Bold) | notosanskr | 기본 본문·자막 |
| Black Han Sans | blackhansans | 초굵은 임팩트 자막(예능·광고 헤드라인) |
| Do Hyeon | dohyeon | 굵은 고딕 |
| Jua | jua | 둥근 귀여운 |
| Gaegu | gaegu | 손글씨 |
| Nanum Pen Script | nanumpenscript | 펜 손글씨 |
| Song Myung | songmyung | 명조(감성·인용) |
| Nanum Myeongjo | nanummyeongjo | 명조 굵은 |
| Gothic A1 (Regular/Black) | gothica1 | 다중 굵기 고딕 |

- **렌더러**: 컴포지션 최상단에 `@font-face` 를 주입한다(`mediaBase` 기준 URL). `document.fonts.ready`
  를 기다려 첫 프레임에서 폰트가 빠지지 않게 한다(Remotion 은 `delayRender`/`continueRender` 로 대기).
- **UI**: 같은 `@font-face` 를 편집기에도 넣어 미리보기·인스펙터가 같은 글꼴로 보이게 한다.
- **인스펙터**: TextSection 에 **폰트 선택 드롭다운**(위 목록 + 시스템 기본). 각 항목을 **그 폰트로**
  그려서 고르기 쉽게 한다.
- **스키마**: `FONT_FAMILIES` 상수(표시명 + CSS font-family 문자열)를 schema 에서 export.
  `TextStyle.fontFamily` 는 지금처럼 자유 문자열 — 목록은 편의일 뿐 제약이 아니다.
- **서버**: `media/fonts/` 는 기존 `/media/*` 정적 서빙에 이미 포함된다(별도 라우트 불필요). 확인만.

### 검증
- 렌더 결과에서 **글자가 실제로 그 폰트로 그려졌는지**: 같은 문구를 서로 다른 두 폰트로 렌더해
  픽셀이 다른지 확인(같으면 폴백된 것).
- 폰트 파일이 없을 때도 렌더가 죽지 않고 시스템 폰트로 폴백되는지.

## T4. 속도 램프 소리 켜기 (G4) — T1 완료 후 (clips.tsx 충돌 회피)

Remotion 은 등속 배속에서 **음정을 이미 보존**한다(실측). 램프를 음소거한 이유는 세그먼트 경계의
클릭음이다. **경계에 짧은 페이드를 넣어 소리를 켠다.**

- 각 램프 세그먼트의 볼륨에 **앞뒤 페이드**를 곱한다. 페이드 길이 = `min(8ms, 세그먼트 길이의 20%)`.
- 클립 전체의 첫 세그먼트 시작·마지막 세그먼트 끝에는 페이드를 넣지 않는다(클립 자체의 fadeIn/Out 과 중복 방지).
- 기존 `fadeFactor`(클립 페이드)와 곱해진다.

### 검증
- 램프 클립을 **실제로 렌더**해서 출력 오디오의 **표본 단위 불연속**을 측정:
  인접 표본 차이의 최댓값이 페이드 없이 렌더한 것보다 확실히 작아야 한다.
- 음정 보존 확인(원본 220/440Hz → 결과도 220/440Hz 부근).

## T5. Real-ESRGAN 업스케일 백엔드 (G5) — **중단. 넣지 않는다.**

**이유: 이 컴퓨터가 다섯 번 다운됐다.**

실행 파일을 받아 시험하는 동안 Windows 가 13:48 · 13:52 · 13:56 · 14:07 · 15:49 에 강제 종료됐다.
전부 **BugCheck 0x00000116 (VIDEO_TDR_ERROR)** — 그래픽 드라이버가 응답을 멈췄고 복구에 실패했다.
- 인과 근거: 실행 파일을 푼 시각이 13:34, 첫 다운이 13:48. 지난 30일 비정상 종료 7회 중 **5회가 이 두 시간 안**.
- 원인으로 지목: **NVIDIA MX450 드라이버가 2020-10-19 판**(27.21.14.5256). VRAM 2GB.
  (같은 컴퓨터의 Intel Iris Xe 는 2025-05-25 판이다.)

**조치**
- 제품 코드에는 **한 줄도 붙이지 않았다.** `upscaleVideo` 는 기존 lanczos 그대로다.
- `scripts/prewarm.mjs realesrgan` 은 남기되 이 사고를 경고로 출력하고 5초 대기한다.
- `vendor/realesrgan/`(51MB)은 디스크에 남아 있지만 **아무것도 실행하지 않는다.** 지워도 무방하다.

**다시 검토할 조건:** 그래픽 드라이버를 최신으로 올린 뒤. 사용자 판단으로 **드라이버는 올리지 않기로 했다**
(평소 사용에는 문제가 없고, 삼성 업데이트 앱에 해당 드라이버가 없을 가능성이 높다). 따라서 **당분간 보류.**

### 고전적 업스케일의 한계 (실측)
"AI 대신 고전 필터를 더 손보면 되지 않나" 를 실제로 재봤다. 270×480 으로 줄이고 crf 34 로 재압축한
소스를 1080×1920 으로 되돌린 뒤 원본과 비교:

| 방식 | PSNR | SSIM |
|---|---|---|
| 그냥 늘리기(bicubic) | 29.48 | 0.921 |
| 현재(lanczos+unsharp) | 29.62 | 0.919 |
| deblock+denoise 추가 | 29.60 | 0.919 |

**셋이 사실상 같다.** 필터 조합으로는 더 짜낼 것이 없다 — 없는 디테일은 안 생긴다.
(한계: 합성 패턴 소스였고, PSNR/SSIM 은 초해상 평가에 잘 안 맞는다. 다만 고전 방식끼리 비교한
결론은 유효하다.)

## 공통 제약

- v1·W5 의 기존 테스트를 **하나도 깨지 않는다**. 깨지면 계약을 먼저 고친다.
